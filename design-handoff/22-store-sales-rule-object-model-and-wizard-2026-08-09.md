# 门店售卖规则对象模型与三步流程

## 1. 最终对象口径

| 规则类型 | 选择方式 | 商品范围 | 说明 |
| --- | --- | --- | --- |
| 商品 | 直接多选商品 | 所选商品 | 同批商品共用经营结果、门店和渠道 |
| 规格 | 先多选商品，再逐个选择完整 SKU 组合 | 所选商品及 SKU | 不把杯型、温度、甜度等规格组值平铺成独立对象 |
| 商品做法 | 从公共做法库按分组多选 | 默认全部关联商品，可收窄到指定商品 | 可一次限制门店内所有关联商品的“去冰”等做法 |
| 商品加料 | 从公共加料库按分组多选 | 默认全部关联商品，可收窄到指定商品 | 可一次限制门店内所有关联商品的“椰果”等加料 |

做法、加料仍保留商品关联关系，但该关系用于计算影响商品，不要求商家在创建普通规则时逐个商品重复勾选。只有局部例外规则才维护指定商品范围。

## 2. 新增与编辑流程

1. 管控对象：填写规则名称，选择对象类型、具体对象与经营结果。
2. 门店与渠道：通过统一门店选择器选店，再选择适用渠道。
3. 校验确认：汇总对象、商品范围、经营结果、门店和渠道，并检查反向冲突后保存。

商品、SKU、公共做法/加料、门店均使用独立选择器承载大量数据。主抽屉只显示已选摘要，不平铺所有选项，避免多规格、多做法和多加料时形成超长表单。

## 3. 校验规则

- 商品规则：同商品、同门店、同渠道且经营结果相反时冲突。
- 规格规则：同一商品下存在相同完整 SKU、同门店、同渠道且经营结果相反时冲突。
- 做法/加料规则：存在相同公共对象后继续比较商品范围；任一规则为“全部关联商品”即视为商品范围有交集，双方均为“指定商品”时仅在商品交集非空时冲突。
- 保存、编辑启用和停用后重新启用均执行校验；冲突未解决不得保存或启用。
- 未配置规则时默认全部适用门店可售/可选，不创建“全部门店可售/可选”的冗余规则。

## 4. 列表与详情摘要

- 商品规则展示商品名称和商品数量。
- 规格规则展示商品数量与完整 SKU 数量，详情按商品展开 SKU 组合。
- 做法/加料规则展示公共对象名称，并标明“全部关联商品”或“指定 N 个商品”。
- 状态列只显示完整可见的可操作开关，通过 Tooltip 和无障碍名称补充状态；删除前必须停用并二次确认，历史审计保留。“更多”菜单使用表格外的页面浮层，避免被滚动容器或后续行遮挡。
