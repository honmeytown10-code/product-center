# 商品中心全域页面模式

## 目录

- 业务域与线上模块地图
- 商品管理列表
- 商品创建、编辑与详情
- 分类、属性、做法与加料
- 配方与营养
- 商品运营、模板与同步
- 门店商品
- 平台商品与映射
- 商品设置与经营规则
- 价格体系
- 日志与审计
- 选择器与批量操作

## 业务域与线上模块地图

| 业务域 | 典型对象 | 主骨架 |
| --- | --- | --- |
| 商品档案 | 标准商品、套餐、SKU、条码 | 搜索表格、分组表单、详情 |
| 分类属性 | 前台分类、后台类目、规格、标签 | 左树右表、配置面板 |
| 配方管理 | 配料、商品配方、营养成分 | 左侧对象定位、分层表格、配置页 |
| 商品运营 | 模板、同步、价格、推荐、互斥/必选规则 | 对象列表、任务步骤、规则配置 |
| 门店商品 | 在售门店、上下架、库存、沽清 | 范围筛选、高密度表格、批量栏 |
| 平台商品 | 在线点商品、第三方商品、团单、商品映射 | 双对象映射、状态表格、任务结果 |
| 商品设置 | 通用参数、自定义属性 | 分组设置页、配置表单 |
| 价格体系 | 策略、渠道、时段、适用门店 | 策略列表/卡片、配置弹窗 |
| 日志审计 | 商品、模板、价格、同步变更 | 筛选表格、前后快照 |

当前线上 `/goodsCenter/**` 页面可按以下模块识别。它用于判断业务域和选择参考页，不用于在业务页面中重复生成导航：

| 一级模块 | 已观察到的页面 |
| --- | --- |
| 商品档案 | 商品管理、商品分类、商品属性 |
| 配方管理 | 配料库、商品配方、营养成分、新商品配方 |
| 商品运营 | 商品同步、模版管理、价格体系、属性互斥、商品推荐、必选商品 |
| 门店商品 | 门店商品管理、门店商品分类、门店商品属性、门店区域 |
| 平台商品管理 | 美团团单、在线点商品、商品映射 |
| 商品设置 | 通用设置、自定义属性 |

具体菜单名、能力与路由以目标项目当前代码和账号权限为准；不得从本规范反向硬编码导航。新增商品中心模块也应触发本 Skill，并按最接近的业务对象和任务骨架归类。

## 商品管理列表

结构：

```text
状态 Tab（全部、可售、停售、草稿等真实状态）
主要筛选（商品 ID、后台分类、商品类型、数据来源）
可保存的快捷筛选与查询/重置
搜索与操作栏（排序、导入导出、更多操作、创建商品）
前台/后台分类树 + 商品高密度表格
分页 / 批量操作栏
```

- 商品列组合缩略图、名称、商品 ID；类型、分类、基础价格、售卖状态和套餐展开等按任务独立成列。
- 状态 Tab、顶部筛选、分类树和表格查询必须作用于同一结果集；任何一处变化都回到第一页。
- 筛选项多时先展示高频条件，再通过“添加筛选/展开筛选”补充，支持保存快捷筛选时必须显示当前条件摘要。
- 搜索框与高级筛选职责分开；搜索用于名称、编码等关键词，不在一个输入框内隐式承担全部条件。
- 排序、导入导出、更多操作和创建商品放在表格操作栏；主操作保持唯一突出。
- 分类树宽度可收起但不得挤压到表格不可用；前台分类与后台分类切换要保留明确上下文。
- 行内只保留编辑、详情等高频动作，低频和危险操作收入“更多”。

## 商品创建、编辑与详情

按业务阶段分组：

1. 基础信息：名称、类型、分类、图片、编码。
2. 商品信息：规格/SKU、条码、单位、配方或套餐子项。
3. 售卖信息：售价、渠道、上下架、库存。
4. 适用范围：组织、门店、区域。
5. 高级设置：标签、展示、营养、扩展字段。

- 标准商品与套餐共用基础骨架，但不要在一个表单中堆满互斥字段。
- SKU 表格保持列对齐，批量填充必须支持撤销或明确覆盖范围。
- 查看态使用详情布局，不简单禁用整张表单。
- 保存前校验；保存中防重复；离开时处理未保存变更。
- 详情页稳定展示商品身份、当前状态、渠道/门店范围和变更记录。

### 主档与渠道商品联合创建及分开维护

- 渠道商品库开启联合创建后仍保留“选择已有主档”，避免重复建立主档；新建菜单只提供标准商品、套餐商品并分别沿用原类目规则。
- 仅允许从主档添加时，“从商品主档添加”作为唯一主操作，渠道商品列表不显示主档编辑入口。
- 允许联合创建且具备主档编辑权限时，可以展示独立的“编辑商品主档”，但不得与“维护渠道资料”合并成一个编辑页。
- 联合创建页不并排展示重复的渠道名称、前台分类、图片、规格售价和继承结构，这些值默认从主档生成；前台分类在主档资料区填写一次，渠道展示资料、售卖设置、补充资料和适用的平台属性仍在同一创建页维护。创建后渠道资料页可覆盖当前商品库前台分类归属，但不得修改分类定义。不要额外堆叠解释继承关系的大块说明卡。
- 主档名称与渠道名称在数据模型中仍是两个字段。渠道名称创建时默认跟随主档；创建后从“维护渠道资料”切换独立设置或恢复跟随，渠道改名不得回写主档。
- 规格/SKU、做法、加料的新增、删除、改名和关系结构属于主档；渠道只维护继承项启用子集和价格、库存、加价等渠道销售值。
- 联合创建按对象分层校验、鉴权和写入；后续编辑分别进入主档页和渠道页、分别保存。创建策略不能替代主档编辑权限。

## 分类、属性、做法与加料

- 左侧分类/分组负责定位，右侧展示当前对象的列表或配置。
- 新建、重命名、排序、删除应使用稳定入口；不可只在 hover 时出现关键动作。
- 拖拽排序必须提供保存/取消，保存前显示“有未保存修改”。
- 属性值、规格值、标签、加料项保持父子层级；禁止把层级压成一串标签。
- 删除前显示关联商品数量；存在引用时优先阻止删除并提供查看入口。
- 属性互斥、必选商品等规则页需用自然语言摘要当前规则，避免只展示配置代码。

## 配方与营养

- 配料库以对象搜索、分类/状态筛选和高密度表格为主；配料身份、单位、营养或引用状态应可定位。
- 商品配方清楚区分商品、规格、配料与用量；多规格配方不得只显示 SPU 汇总而隐藏 SKU 差异。
- 配方编辑优先使用左侧商品/规格定位与右侧配料明细，或分组表单；避免将复杂关系塞入一个小弹窗。
- 营养成分展示单位、每份/每百克口径、计算来源和覆盖规则；数值 `0` 与未配置保持区分。
- 替换或删除配料前显示被商品配方引用的数量和影响范围。

## 商品运营、模板与同步

结构：

```text
选择源与目标范围
选择商品/模板
展示字段映射或差异
预校验冲突
确认覆盖范围
执行任务
结果与失败明细
```

- “新增”“覆盖”“跳过”“冲突”使用文字和数量摘要。
- 不把长任务伪装成即时成功；复用下载中心或任务中心反馈。
- 覆盖同步必须说明影响门店、渠道、字段和不可逆项。
- 平台商品和企迈商品的真源必须清楚，不能暗示双向自动同步。

商品推荐、属性互斥和必选商品属于经营规则配置：

- 明确规则对象、触发条件、适用范围、优先级和当前启用状态。
- 用自然语言摘要规则结果，并提供查看关联商品的入口。
- 规则冲突、循环依赖和无效对象必须在提交前校验。
- 门店售卖规则存在反向范围冲突时禁止保存或启用，引导用户调整本次范围或编辑原规则；正常列表不把可预防的冲突作为常态筛选和状态展示。
- 门店售卖规则列表使用“规则详情、适用门店、适用渠道、经营结果”等商家语言；规则导出不得命名为“导出影响范围”，也不展示“命中对象”等执行过程指标。状态列在空间受限时只显示真实开关，通过 Tooltip 和无障碍名称补充“已启用/已停用”，并在启停前确认。
- 商品与规格合并为“商品 / 规格”规则：先多选商品，默认覆盖整个商品的全部有效 SKU；需要细分时，仅从当前商品实际关联的规格组中选择规格值，并将所选值展开为所有包含该值的 SKU 并集。禁止跨商品混选规格值，也不让用户逐条勾选完整 SKU 组合。做法和加料规则直接选择公共做法/加料定义，默认作用于全部关联商品；只有例外场景才选择“指定商品”收窄作用范围。未配置规则即表示全部适用门店可售/可选，不额外创建全量正向规则；两种局部门店结果都通过统一门店选择器选择并回显。
- 新增/编辑使用“管控对象 → 门店与渠道 → 校验确认”三步流程；对象数量多时通过独立商品、SKU、做法/加料和门店选择器承载，不在长抽屉中平铺所有选项。
- 状态开关必须完整可见，不得被固定操作列遮挡；删除规则前必须先停用并二次确认，删除后保留审计，不能暗示已发布商品会自动回滚。行内“更多”菜单必须脱离表格滚动裁切层或使用统一浮层组件。
- 启用、禁用和修改范围时说明影响门店、渠道与生效时间。

## 门店商品

- 页面始终明确当前机构/门店、当前操作渠道和统一/独立库存模式。
- 开启全渠道统一库存时隐藏单渠道切换；否则一次只选择一个基础渠道，不展示渠道分组作为可操作渠道。
- 搜索结果严格属于当前范围；左侧异常/分类列表与右侧主列表同步过滤。
- 上下架、库存、沽清状态使用文字；异常可增加角标。
- 多规格沽清默认“按商品统一设置”，可切到“按规格独立设置”。
- “取消沽清”会恢复无限库存时必须二次确认并写明后果。
- 批量操作持续展示选中数量、门店、渠道和影响对象，结果展示部分成功明细。

## 平台商品与映射

- 并列展示企迈商品与平台商品的身份、规格、状态和映射关系；不得只凭名称暗示已经匹配。
- 清楚标识数据真源、同步方向、最近同步时间与失败原因。
- 未映射、映射冲突、平台对象失效和渠道未开通是不同状态。
- 自动匹配结果必须可复核；手动映射支持搜索、已选对象和解除映射确认。
- 团单、在线点商品等渠道专有字段使用对应渠道局部配置，不把渠道色扩展为全页主题。

## 商品设置与经营规则

- 通用设置按能力分组，展示当前值、默认值、作用范围和修改后生效方式。
- 自定义属性清楚区分属性定义、可选值、适用商品类型与已引用商品。
- 全局/品牌/门店级配置不得混在同一层级而不显示继承来源。
- 设置项数量较多时使用左侧分组或锚点导航，右侧保持单列稳定表单。
- 修改影响历史商品或下游渠道时必须先解释影响范围，再允许保存。

## 价格体系

`/goodsCenter/priceGroup` 的核心模式是“少量复杂策略对象”，这是可使用卡片而非纯表格的明确例外。

### 列表结构

1. 紧凑筛选：策略 ID、策略名称、机构门店、启用状态。
2. 轻量说明：解释差异化价格能力并提供帮助入口。
3. 操作栏：主按钮“新增价格策略”，次入口“价格策略说明”。
4. 策略对象：名称、ID、启用状态、下发渠道、生效日期/周期/时段。
5. 高频动作：价格管理、适用门店、编辑策略；低频动作收入“更多”。

当策略数量大、需要排序/批量处理或字段增加时改用表格；不要机械坚持卡片。卡片保持 2 列桌面布局、紧凑间距和清晰边界，不做营销海报式大卡片。

### 新建/编辑

- 中等字段量可用约 720–840px 弹窗；复杂价格矩阵改用独立页面。
- 基础字段：策略名称、描述、启用状态。
- 生效规则：日期、周期、时段，明确时区和冲突优先级。
- 渠道范围：小程序、POS、外卖等真实业务渠道及堂食/外带等子场景。
- 适用范围：机构、区域、门店，显示已选数量并支持查看。
- 价格管理：按商品/SKU 展示原价、策略价、差额和校验结果。

### 风险控制

- 启用前检查同门店、同渠道、同时段的策略冲突。
- 禁用、删除、缩小适用门店或修改生效时间时说明影响范围。
- 价格为 `0` 与未配置必须区分；金额精度跟随现有业务规则。
- 记录策略新建、删除、启禁用、生效规则、适用门店和商品价格变更。

## 日志与审计

- 筛选包含模块、操作类型、对象 ID/名称、操作人、时间。
- 行摘要回答“谁在何时对什么做了什么”。
- 详情展示变更前/后值、范围、结果和失败原因。
- 商品、模板、价格体系等复杂对象可展示页面快照，但快照不能替代结构化差异。

## 选择器与批量操作

- 选择器使用“搜索/树或表格/已选区/确认”结构。
- 显示已选数量，支持去除单项和清空。
- 关闭弹窗后按业务决定保留还是清除选择，并保持同模块一致。
- 批量操作栏尽量靠近数据表底部，持续显示选中数与当前范围。
