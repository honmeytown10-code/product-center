# 商品中心 Next 工作流与状态

## 商品准备流程

### 统一管理

```text
商品主档创建身份与结构
或：从默认渠道商品库新建 → 填写主档资料与结构 → 继承共用字段并填写渠道属性 → 单次校验与提交 → 同时创建主档和默认渠道商品
→ 直接发布或加入模板
```

### 分渠道协作

```text
建立主档 → 渠道团队收到待办 → 从主档加入渠道商品库 → 维护销售资料与平台扩展 → 发布
或（品牌开启且具备双重权限）：当前商品库新建 → 填写主档资料与结构 → 继承共用字段并填写渠道展示/售卖/平台属性 → 同时创建并加入当前商品库 → 发布
```

“同时创建”不得生成独立商品身份。提交前先按名称、编码、条码和 SKU 等规则查重；命中疑似主档时优先引导选择已有主档。只有渠道商品权限、没有主档创建权限的用户不得绕过主档权限，可提交创建申请或转交商品团队。

创建后维护分为两条明确链路：

```text
维护渠道资料 → 只编辑当前渠道商品名称、展示资料、售卖设置、库存等渠道值和继承项启用范围；规格售价继承主档
编辑商品主档 → 进入独立主档编辑页 → 校验主档编辑权限 → 保存主档并生成下游影响/确认任务
```

联合创建时不重复展示渠道名称、前台分类、图片、规格售价和继承结构；系统以主档对应值生成渠道商品，渠道名称和前台分类初始为“跟随主档”，所有规格售价直接继承本次填写的主档规格售价。展示资料、售卖设置、补充资料和平台专属属性仍可在创建时填写。创建后渠道商品可独立设置当前商品库的名称与前台分类；独立值不回写主档，恢复跟随时以主档当前值覆盖。渠道页只能选择主档已定义的前台分类，不能修改分类定义。规格、做法、加料结构变化只从独立主档编辑页发起，并为受影响渠道生成确认任务。仅从主档添加模式不在渠道商品页提供主档编辑入口。

### 平台自行维护

```text
建立主档 → 选择企迈经营能力 → 加入渠道商品库 → 下发企迈侧门店渠道商品 → 平台维护真实商品 → 拉取平台商品 → 自动或人工映射 → 接单或经营操作
```

若平台维护资料且未启用任何企迈经营能力，可跳过渠道商品库、企迈侧商品下发、门店绑定和映射；一旦启用接单或上下架/库存中的任一能力，上述链路均为必需。

## 发布流程

```text
选择来源与目标 → 自动判定来源 → 发布前校验 → 确认范围 → 固定快照与发布批次 → 拆分任务 → 汇总结果 → 重试失败范围
```

- 一个用户提交动作只形成一个发布批次。
- 企迈侧渠道合并为一个同步任务；三方平台任务按平台拆分。
- 任务使用固定快照，重试不读取漂移后的资料。
- 平台失败不回滚其他已成功渠道。
- 读取新资料必须重新创建发布批次。

## 映射与巡检闭环

```text
发布或生成镜像 → 建立/校验映射 → 未映射、冲突、失效进入治理 → 显示影响 → 修正 → 审计
平台侧变化 → 差异巡检 → 判断维护方式 → 覆盖平台 / 接受平台值 / 忽略 / 仅处理映射风险
```

## 状态矩阵

| 对象 | 核心状态 |
| --- | --- |
| 商品准备 | 待完善、待渠道确认、可发布、已归档 |
| 发布批次 | 校验中、发布中、部分成功、发布失败、已完成 |
| 三方企迈管理渠道 | 未启用、待配置、可发布、发布中、已发布、发布失败 |
| 平台自行维护渠道 | 企迈侧未下发、待平台商品、待映射、已映射、映射异常 |
| 映射 | 未映射、推荐待确认、已映射、冲突、失效 |
| 授权 | 无需授权、待授权、授权中、已授权、即将到期、已过期、权限不足、余额不足/能力暂停 |
| 差异 | 无差异、待处理、已忽略、处理中、已恢复 |

每个状态必须同时提供含义、影响范围、下一步动作和更新时间；颜色与图标只能辅助文字。

## 交互约束

- 页面顶部持续显示当前品牌、商品库/渠道和门店范围上下文。
- 危险操作确认说明对象、渠道、门店、商品/SKU 数、生效时间和不可逆部分。
- 批量结果显示总数、成功数、失败数、等待数及失败明细。
- 筛选为空保留条件并允许清空；无权限不能伪装为空数据。
- 商品库切换器、工作台计数、待办、导入导出和发布目标只展示由当前用户固定渠道权限与动态分组关系推导出的获权商品库；有页面权限但没有任何商品库数据范围时显示明确无权限状态。分组变化不得自动扩大固定渠道权限。
- 跨商品库批量操作按有权范围拆分；包含无权对象时禁止静默跳过，必须给出无权数量和处理方式。
- 跨页流程完成后回到可验证结果的位置，例如发布批次详情或已修复的治理清单。
- 工作台卡片必须是可行动待办，不展示没有处置入口的装饰性指标。
