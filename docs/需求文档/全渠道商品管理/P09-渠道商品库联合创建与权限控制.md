# P09 渠道商品库联合创建与权限控制需求文档

> 文档状态：v1.1 评审稿 · 2026-08-25（补充渠道做法/加料仅启停的操作边界）

## 1. 需求目标

在不改变商品主档与渠道商品对象边界、不改变标准/套餐商品及其原有类目和字段规则的前提下：

1. 保证统一管理与分渠道协作的菜单结构稳定；
2. 支持从渠道商品库一次创建商品主档和当前渠道商品；
3. 支持不同人员只查看和管理被授权的渠道商品库；
4. 避免模式切换、批量操作、导入导出、发布及列表统计造成越权；后续工作台接入时复用同一权限口径。

## 2. 角色与典型任务

| 角色 | 典型任务 |
| --- | --- |
| 品牌管理员 | 配置协作方式、创建方式、商品库及权限；确认模式切换影响 |
| 商品负责人 | 创建和维护商品主档，处理渠道团队提交的主档申请 |
| 渠道负责人 | 在获权商品库选择已有主档，维护渠道资料；获双重权限时联合创建 |
| 发布负责人 | 发布获权商品库的商品并处理失败 |
| 审计/实施 | 查看配置、权限和迁移记录，不默认获得经营编辑权限 |

## 3. 配置需求

### 3.1 协作方式

- 枚举：统一管理、分渠道协作。
- 切换不改变菜单结构。
- 统一管理运行时只生成一个品牌默认商品库视图；原分组配置保留但不作为运行时多商品库展示。
- 分渠道协作按已配置分组生成商品库，并校验所有需要企迈侧门店渠道商品的渠道都已归属商品库。

### 3.2 渠道商品库创建方式

- 字段：`channelProductCreationMode`。
- 枚举：`existing_master_only`、`create_master_and_channel`。
- 配置层级：品牌。
- 统一管理推荐值：`create_master_and_channel`。
- 分渠道协作推荐值：`existing_master_only`，但允许品牌开启联合创建。
- 修改后写入配置审计，记录修改人、修改前后值、品牌和时间。

## 4. 页面与交互需求

### 4.1 菜单

统一管理和分渠道协作均展示：

- 商品资料 / 商品主档；
- 渠道经营 / 渠道商品；
- 渠道经营 / 渠道属性。

模式切换不得导致当前页面找不到入口；历史链接继续进入相同页面并按当前模式展示一个或多个商品库。

### 4.2 渠道商品页

**页面图示：渠道商品库入口与建品操作**

![渠道商品库入口](./assets/P09-joint/01-渠道商品库入口.png)

**功能与交互说明**

- 统一管理与分渠道协作保持相同菜单；区别只在品牌默认商品库或多个获权商品库。
- `existing_master_only` 时“从商品主档添加”为唯一主操作，列表不出现主档编辑入口。
- `create_master_and_channel` 时“新建商品”为主操作，“选择已有主档”为次操作；是否允许编辑主档继续独立鉴权。
- 商品库切换、计数、筛选、选品、导入导出和发布只使用账号固定渠道权限推导的可见范围。

- 商品库切换器只展示用户获权商品库；统一管理只有一个默认商品库时不做多项切换。
- 页面持续显示当前商品库名称、包含渠道、用户权限摘要和待处理数量。
- `existing_master_only`：主操作为“选择已有主档”。
- `create_master_and_channel`：在两种协作模式下均显示“选择已有主档”和“新建商品”。已存在当前商品库渠道商品的主档不可重复选择；仅存在主档的商品可补建渠道商品。
- “新建商品”菜单固定为标准商品、套餐商品两项。

### 4.3 类目选择

- 标准商品只展示原标准商品可选类目；套餐商品只展示原套餐商品可选类目。
- 类目来源、顺序、禁用态、默认值、字段联动和校验完全沿用原商品创建逻辑。
- 切换商品类型需重新选择相应类目，不复用另一类型的类目或互斥字段。

### 4.4 联合创建表单

**页面图示：联合创建主档与渠道商品**

![联合创建表单](./assets/P09-joint/02-联合创建表单.png)

**功能与交互说明**

- 先选择标准商品/套餐商品及各自可用类目，再进入同一长表单；不新增第三种商品类型。
- 主档基础资料和商品结构填写一次，渠道展示、售卖、补充资料与适用平台属性在渠道分区继续填写。
- 渠道名称、主图、前台分类、规格结构和首次销售价默认从本次主档输入生成，不重复作为第二套必填项。
- 一次保存创建两个独立对象并建立引用；任一步失败不留下半条可见商品，保留输入用于修复重试。

表单标题明确“新建标准/套餐商品（主档 + 渠道商品）”。创建页遵循“共用资料一次填写、渠道属性同页维护”，至少按以下章节展示：

1. 主档基础资料；
2. 主档商品结构；
3. 渠道展示资料；
4. 渠道售卖资料；
5. 渠道补充资料；
6. 当前商品库适用且由企迈维护的平台专属属性。

不得把同一业务信息复制为主档和渠道两套输入。渠道商品按以下默认映射生成：

| 渠道字段 | 创建默认值 | 创建页展示 |
| --- | --- | --- |
| 渠道商品名称 | 主档商品名称，状态为 `follow_master` | 不展示重复输入 |
| 渠道图片 | 主档主图 | 不展示重复上传 |
| 前台分类 | 商品主档中选择的默认前台分类，状态为 `follow_master` | 在联合创建的主档资料区填写一次，渠道资料区不重复输入；创建后可在“维护渠道资料”中覆盖当前商品库归属 |
| 规格、做法、加料 | 完整继承主档结构与启用范围 | 不重复创建结构；渠道启用范围按默认值生成，后续做法/加料只允许启用或禁用 |
| 渠道规格售价 | 主档规格售价 | 不展示渠道售价输入，保存时直接继承主档规格售价 |
| 平台专属字段 | 无法继承，按平台规则填写 | 仅命中适用平台且由企迈维护时展示 |

渠道列表简述、详情描述、标签、角标、起购/限购、分时段销售、售卖方式及其他渠道属性没有主档重复项，应在联合创建页直接维护。字段归属、是否必填、校验和渠道动态条件仍以商品主档、渠道商品的数据模型为准。界面省略重复输入不代表合并对象；服务端必须分别写入主档和渠道商品，并记录继承状态与渠道属性值。

### 4.5 维护资料

- 渠道商品列表默认行操作为“维护渠道资料”，打开渠道范围表单，只修改当前商品库对象。
- 不提供“维护主档与渠道”联合编辑入口。创建可以编排两个对象，编辑必须按对象分别进入、分别鉴权、分别保存。
- `existing_master_only` 模式下，渠道商品列表不得展示主档编辑入口，即使用户另外拥有主档编辑权限，也应从“商品主档”菜单完成该任务，保持渠道负责人职责单一。
- `create_master_and_channel` 模式下，同时拥有 `product_master.edit` 时可显示独立的“编辑商品主档”，打开商品主档编辑页；没有该权限时隐藏。
- 从渠道商品库进入独立主档编辑页并保存后，成功页的“更新渠道商品”不得直接跳转渠道商品库；点击后复用主档列表同步弹窗：主档控制属性固定同步且不可取消，渠道可维护属性允许勾选，再选择有权渠道商品库并即时更新。入口来源不限制只能选择当前商品库，最终范围仍按固定渠道权限动态推导。
- 联合创建页只填写“主档商品名称”，不显示“当前渠道商品名称”重复输入；系统以 `follow_master` 状态创建渠道名称。
- 创建后在“维护渠道资料”中可将渠道名称切换为 `independent`（独立设置）；独立名称只改当前渠道商品，点击“恢复跟随主档”时以主档当前名称覆盖渠道名称。
- 创建后“维护渠道资料”中的前台分类默认显示主档值并标识来源；用户可从主档已定义的启用分类中重新选择，保存后仅覆盖当前商品库，不回写主档。清除覆盖并“恢复跟随主档”后读取主档最新默认值。
- 渠道商品页只维护商品与前台分类的归属关系，不提供新增、改名、移动、停用分类定义；分类定义仍由商品主档“分类与属性”统一维护。
- 规格/SKU、做法、加料的结构增删改只在独立主档编辑页进行。渠道编辑页中规格/SKU可按既有规则维护启用范围、渠道库存等销售值；做法、加料只展示主档继承项的启用/禁用开关，不提供选择、新增、删除、改名、重排或加料购买限制编辑入口。
- 主档结构修改提交前展示受影响商品库、渠道商品和发布任务；保存后对需人工确认的商品生成渠道确认任务。
- 创建方式和编辑权限独立判断。`create_master_and_channel` 不等于拥有 `product_master.edit`，提交载荷不得包含无权字段。

### 4.6 提交与结果

- 保存按钮防重复提交。
- 提交前同时执行主档与渠道资料校验、重复商品检测、当前商品库有效性和权限校验。
- 联合创建成功结果显示：新主档 ID、当前商品库、渠道商品状态“未发布”，并明确主档与渠道商品已经同时创建且渠道商品已自动加入当前商品库。
- 联合创建成功页只保留“继续编辑 / 继续创建 / 返回渠道商品库”等结果动作，不再提示“添加至渠道商品库”，也不展示“同步至门店 / 更新模板”后续任务卡片。
- 商品主档菜单创建主档成功后，“添加商品至渠道商品”入口打开紧凑的单步骤商品库多选弹窗，不显示步骤编号，确认后按主档当前资料即时创建渠道商品；商品主档编辑成功后，“更新渠道商品”入口打开与主档列表一致的属性与商品库选择弹窗，确认后即时更新。两类单商品操作均不创建后台同步任务。
- 编辑渠道商品成功后，可展示“同步至门店”和“更新商品模板”两个可选入口，分别携带当前商品、商品库和版本上下文跳转到对应流程；用户可不选择，保存结果不受影响，两项任务均不得自动执行。
- 部分失败不得显示完整成功；需说明主档与渠道商品各自结果、失败原因和恢复动作。
- 返回列表后定位新商品并保留当前商品库上下文。

## 5. 权限需求

### 5.1 权限模型

权限判定顺序：页面权限 → 固定渠道数据范围 → 按当前分组推导商品库范围 → 操作权限 → 字段权限。

| 权限 | 作用 |
| --- | --- |
| 渠道商品页面查看 | 是否可进入渠道商品页 |
| 固定渠道范围 | 可查看、选择或管理的固定 channelId 集合；是动态分组变化时的稳定授权基础 |
| 推导商品库范围 | 系统根据当前渠道—商品库分组关系，计算账号当前可见/可操作的商品库 ID 集合 |
| 选择已有主档 | 可把已有主档加入当前商品库 |
| 商品主档创建 | 可创建新的主档身份与结构 |
| 渠道商品创建 | 可在当前商品库创建渠道商品 |
| 渠道商品编辑/移出 | 可修改或移出当前商品库商品 |
| 导入/导出/发布 | 对当前商品库分别授权 |
| 商品库管理 | 新建、改名、删除、调整渠道归属 |
| 商品库授权 | 给角色或用户分配商品库范围和操作，独立高风险权限 |

### 5.2 联合创建权限

联合创建按钮显示条件：

```text
品牌创建方式 = create_master_and_channel
且具备 product_master.create
且当前商品库在数据范围内
且具备当前商品库 channel_product.create
```

不满足主档创建权限时不允许直接创建，可保留“选择已有主档”；若后续接入申请流，显示“申请创建主档”，由商品负责人审核后再进入当前商品库。

### 5.3 范围隔离

- 渠道是固定权限资源，渠道商品库是动态业务分组。页面每次查询先读取账号获权 channelId，再与当前有效分组求交，推导可见商品库；不得仅因用户有“渠道商品”菜单权限就返回全部商品库。
- 账号拥有商品库内任一渠道查看权限时，可看到该商品库及自己有权渠道的摘要；需要修改商品库公共资料、批量修改、导入、导出或发布时，必须满足该操作所要求的商品库完整渠道权限，或由权限中心显式授予跨渠道共享资料操作权限。
- 分组新增、合并、拆分或调整渠道归属后，系统立即按固定渠道权限重新推导商品库范围，不自动扩大账号的固定渠道权限；权限变化和被移除范围必须审计。
- 只返回推导有权商品库及其商品、分类计数、待办、发布任务和日志；商品库切换器、来源选择器和批量目标选择器使用相同口径。
- 商品主档搜索可按独立主档查看权限控制；选择器不得借渠道商品权限泄露无权主档敏感字段。
- 导出只含有权范围；导入逐行校验目标商品库和操作权限。
- 服务端必须校验，前端隐藏按钮不能替代鉴权。
- 有页面权限但没有商品库范围时显示无权限说明和申请路径，不显示“暂无数据”。

### 5.4 同步与批量工具权限

- “发布商品至门店”选择渠道商品来源时，渠道商品库必须单选；选定商品库后，商品选择器和可选渠道都只读取该库及账号有权渠道，切换商品库清空已选商品和渠道。
- 批量修改先选择商品来源：商品主档，或一个渠道商品库。渠道商品库来源同样单选，随后只选择该库商品，不能把多个商品库的同名字段混在一次选品中。
- 批量修改第二步选择商品模板或门店渠道商品时，均提供“全部/指定”范围：全部模板指包含所选商品且账号有权维护的全部模板；全部门店指提交时账号有权门店快照，不包含无权范围。指定模式打开统一模板/门店选择器并保存明确 ID。
- 一次任务的来源、商品、模板、商品库、渠道和门店范围在提交时固定快照；服务端对每个目标重校验权限，禁止只靠前端隐藏无权项。

## 6. 模式切换与权限迁移

### 6.1 分渠道协作切统一管理

保存前影响分析必须包含：商品库数量、商品数量、字段冲突、待发布任务、原商品库人员与角色权限。

- 原部分商品库用户不自动获得统一默认商品库权限；
- 品牌管理员需明确选择默认商品库的查看、维护、创建和发布角色；
- 未确认授权的用户默认不增加范围；
- 保存原商品库、商品关系和权限快照用于回滚。

### 6.2 统一管理切分渠道协作

- 恢复原商品库 ID、渠道归属和权限；
- 统一期间新增商品按目标渠道进入待分配清单；
- 统一期间新增用户权限不得自动复制到全部恢复商品库，由管理员确认；
- 迁移以批次记录状态、失败项、重试和审计。

## 7. 状态与异常

| 场景 | 页面行为 |
| --- | --- |
| 无页面权限 | 无权限页，不显示业务数据 |
| 有页面权限、无商品库范围 | 明确提示未分配商品库权限 |
| 部分商品库权限 | 只展示获权商品库，不展示被隐藏范围总数 |
| 创建方式关闭 | 不显示联合创建入口 |
| 无主档创建权限 | 隐藏联合创建，保留选择已有主档或申请入口 |
| 疑似重复主档 | 阻止直接提交，展示候选主档和选择入口 |
| 主档成功、渠道商品失败 | 部分失败页，支持继续创建渠道商品或撤销孤立草稿 |
| 商品库被删除/权限被收回 | 阻止提交，保留表单草稿并要求切换有权商品库 |
| 并发重复提交 | 幂等返回首次结果，不重复创建 |

## 8. 数据与接口约束

- channelId 是基础数据权限的稳定资源；商品库 ID 用于业务归属和任务快照，不单独取代固定渠道权限。商品库改名不改变推导结果，分组调整按最新 channelId 关系重算并审计。
- 联合创建请求携带品牌、商品库 ID、商品类型、类目 ID、主档字段、渠道字段、平台字段和幂等键。
- 服务端按字段归属分别写入主档与渠道商品，并建立引用关系。
- 权限校验返回明确错误类型：无页面权限、无商品库范围、无主档创建权限、无渠道商品创建权限、字段无权。
- 本期列表、计数、导出和发布接口统一接收并校验商品库数据范围，禁止只靠前端筛选；后续工作台接入时必须复用同一服务端校验能力。

## 9. 验收用例

1. 统一管理与分渠道协作互切，菜单结构和顺序不变。
2. 统一管理只显示一个品牌默认商品库。
3. 分渠道协作用户 A 只授权 POS、小程序堂食渠道，只能看到由这些固定渠道推导出的商品库范围；分组调整后仍不得看到外卖、在线点等无权渠道数据。
4. 联合创建关闭时，渠道商品页只可选择已有主档。
5. 联合创建开启且具备双重权限时，标准商品和套餐商品均先进入各自原类目选择器。
6. 联合创建成功后，商品主档和当前商品库各产生一个相互引用的对象，不产生第二套 SKU 身份。
7. 只有渠道商品创建权限、没有主档创建权限时，不能直接联合创建。
8. 模式合并时，原部分商品库权限不会自动扩大；未完成新授权确认不能保存迁移。
9. 导入、导出、批量修改、发布和列表统计均严格遵守商品库范围；工作台不属于本期验收。
10. 重复提交、权限并发收回和部分失败都有明确恢复路径与审计记录。
11. 统一管理开启联合创建时仍可选择已有主档，已存在渠道商品的主档不可重复添加。
12. 标准商品和套餐商品均可从“新建商品”菜单进入，菜单不得被容器裁切。
13. 修改主档名称时仅同步跟随状态的渠道名称；独立渠道名称不变。
14. 发布商品至门店选择渠道商品库时只能单选；切换商品库后商品和渠道选择清空并按新库重载。
15. 批量修改可选择商品主档或一个渠道商品库作为来源；模板和门店目标均支持全部有权范围或指定 ID 范围。
14. 渠道维护页修改渠道商品名称不会回写主档名称。
15. 渠道页不能新增/删除/改名主档规格、做法或加料，只能维护继承子集与销售值。
16. 联合创建页不重复展示渠道名称、渠道图片和渠道结构；保存后渠道对象取得主档对应值并记录继承状态。
17. 前台分类在联合创建的主档资料区填写并落入商品主档；渠道商品按 `follow_master` 生成，不在创建页重复输入。创建完成后可在渠道维护页保存当前商品库覆盖值，且不得回写主档或影响其他商品库。
18. 联合创建页不展示渠道规格售价输入；渠道商品全部规格售价取本次提交的主档规格售价，并记录为主档继承来源。
19. 渠道维护页可选择主档已定义的启用前台分类，列表筛选、详情、导出和发布均使用 `当前商品库覆盖值 > 商品主档默认值` 的最终结果；渠道页不得创建或修改分类定义。
20. 渠道维护页的做法和加料均只展示主档继承项及启用/禁用开关；页面不存在选择、新增、删除、改名或结构修改入口。
21. 渠道启停做法或加料只影响当前商品库，不回写主档或其他商品库；主档已停用项在渠道侧强制禁用且不可重新开启。
22. 联合创建成功页不出现重复添加渠道商品、同步门店或更新模板入口；编辑渠道商品成功页可选择同步至门店或更新模板，也可直接返回，跳过不影响本次保存结果。
23. 商品主档创建成功页通过弹窗选择有权商品库后即时添加渠道商品；商品主档编辑成功页（含从渠道商品库进入的独立主档编辑）通过弹窗选择属性和有权商品库后即时更新渠道商品；以上单商品操作均不生成同步任务。
