# 商品中心 Next 迁移规则

## 迁移原则

1. 先建立新对象、状态和任务口径，再迁移菜单。
2. 现有路由保留过渡期，通过重定向进入新页面并携带原筛选上下文。
3. 高风险配置切换必须先做影响分析、迁移批次、失败回滚和审计。
4. 历史平台商品 ID、映射、订单引用和发布快照不因菜单迁移删除或重建。
5. 新旧入口并存时明确推荐入口和退场日期，禁止长期双写或双重心智。

## 旧功能到新入口

| 旧入口 | 新入口 |
| --- | --- |
| 商品管理 | 商品资料 / 商品管理或商品主档 |
| 商品分类、商品属性 | 商品资料 / 分类与属性 |
| 配料库、商品配方、新商品配方、营养成分 | 商品资料 / 配方与营养的页内视图 |
| 商品模板 | 渠道经营 / 商品模板 |
| 价格体系、属性互斥、必选商品、售卖范围 | 渠道经营 / 销售规则的相应视图 |
| 商品推荐 | 渠道经营 / 商品推荐 |
| 商品同步、菜单同步、同步记录 | 发布与治理 / 发布中心 |
| 门店商品、门店分类、门店属性、门店区域 | 门店执行 / 门店商品的页内视图 |
| 平台菜单管理 | 企迈管理渠道进入渠道商品；平台维护渠道进入映射治理 |
| 商品映射 | 发布与治理 / 映射治理 |
| 通用设置、自定义字段 | 配置 / 商品设置 |

批量修改按字段归属进入商品、渠道商品、销售规则或门店商品；执行记录统一进入任务记录，不再把“商品同步”当作所有批量工具的容器。

## 分阶段上线

### 阶段 1：统一入口和口径

- 上线商品设置内的全渠道商品管理策略、发布与映射状态统一展示；商品工作台后置，本阶段默认进入商品主档。
- 新菜单先聚合现有页面，建立旧路由映射与行为埋点。
- 补齐未映射、冲突、失效和门店高频批量操作。

### 阶段 2：切换核心对象与流程

- 上线稳定的“商品主档 / 渠道商品”菜单和渠道商品库；协作方式切换不再增删菜单。
- 上线渠道商品库“选择已有主档 / 同时创建主档与渠道商品”品牌级策略和分区表单。
- 将平台商品资料迁入渠道商品，将同步入口迁入发布中心。
- 上线来源自动判定、固定快照、任务拆分和失败重试。
- 完成协作方式及渠道跨分组的受控迁移。

## 协作方式与权限迁移

- 分渠道协作切到统一管理时，多商品库合并为一个品牌默认商品库，但原商品库配置、商品关系和权限快照需保留，便于回滚。
- 切换前必须展示商品数量、重复/冲突资料、待发布任务、负责人和商品库权限影响，不得只修改菜单或前端显示。
- 原仅拥有部分商品库权限的用户不得自动获得默认商品库全量权限。品牌管理员需要在迁移确认中重新指定默认商品库的查看、维护、创建和发布角色；未确认前相关用户不获得新增范围。
- 统一管理切回分渠道协作时，优先恢复原商品库 ID 与授权；新产生的商品和人员权限进入待分配清单。
- 商品库重命名不改变权限；删除或合并商品库前必须处理仍绑定的角色、用户、待办与发布任务。

### 阶段 3：治理和开放

- 上线差异巡检、版本与试点发布。
- 接入开放 API、Webhook 和跨渠道数据质量指标。
- 关闭旧平台商品和旧同步入口，只保留历史查询与重定向。

## 兼容与退场

- 菜单别名只用于搜索和新手引导，不同时显示两个正式入口。
- 旧链接跳转后提示“已迁移到新入口”，并提供一次性定位说明。
- 迁移期间记录旧入口访问量、任务完成率、发布失败率和人工支持量。
- 只有关键任务成功率与问题恢复能力达到验收标准后，才关闭旧入口。
