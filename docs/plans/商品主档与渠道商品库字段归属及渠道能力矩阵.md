# 商品主档与渠道商品库字段归属及渠道能力矩阵

> 文档定位：作为《商品中心全渠道商品管理产品方案》和 P02《商品主档与渠道商品库》的字段专项补充，用于统一字段归属、继承规则、渠道差异和后续 PRD、数据模型、页面设计口径。  
> 文档状态：V1.0，内部评审稿 · 2026-08-09。  
> 权威关系：P02 定义字段层级、继承覆盖和最终值规则；本文展开存量字段编码与渠道能力。如有冲突，以 P02 为准。  
> 参考资料：类目字段划分飞书文档、现有商品创建编辑字段目录、全渠道商品管理方案、渠道商品库原型及已知平台字段示例。  
> 校对说明：飞书链接在当前环境需要登录，无法直接读取原表内容；本文已按仓库内现有类目动态字段目录逐项归类。标记为“待平台确认”的字段，后续需结合飞书原表及平台接口能力再次校对。

## 1. 核心结论

### 1.1 不能只划分为两张扁平字段表

未来商品资料至少需要区分以下四类数据：

| 数据层 | 回答的问题 | 典型内容 | 权威方 |
|---|---|---|---|
| 商品主档 | 这个商品是什么 | 商品身份、商品类目、SKU、规格结构、条码、商品标识、计量方式与基础关系 | 商品中心 |
| 渠道商品库公共售卖资料 | 这一组渠道如何售卖这个商品 | 渠道展示名称、图片、基础售价、描述、杯贴资料、售卖规则、做法和加料售卖配置 | 商品中心 |
| 具体渠道扩展资料 | 在某一个渠道发布时还需要什么 | 平台类目、平台特色、属性互斥、平台专属图片和规则 | 商品中心存储，平台能力规则驱动 |
| 平台执行状态 | 商品在平台上处理到哪一步 | 平台商品 ID、发布状态、审核状态、失败原因、映射状态 | 平台服务 |

因此，“渠道商品库中的一条商品”在产品上仍是一条记录，但内部应包含：

```text
渠道商品
├── 引用的商品主档及 SKU 身份
├── 渠道分组共享售卖资料
├── 分具体渠道的覆盖值与扩展资料
└── 平台执行结果摘要（只读）
```

### 1.2 商品主档保持纯净，不等于只保留商品名称

商品主档应保留：

- 稳定的商品和 SKU 身份；
- 不因售卖渠道变化而变化的商品事实；
- 规格、做法、加料、套餐等公共结构与可用关系；
- 内部经营、统计、供应链和开放接口需要的主数据。

商品主档不应保留：

- 实际销售价格、市场价、包装费；
- 售卖时间、限购、库存和上下架；
- POS 商品皮重、杯贴生产地和原料说明；
- 配方引用、营养成分引用等应在对应业务页面维护的关联字段；
- 渠道展示标签、角标、详情页营销内容；
- 美团、淘宝闪购、抖音等平台专属字段；
- 平台发布、审核和映射状态。

### 1.3 商品主档在 SKU/规格上维护标准销售价

“价格”不是统一商品身份，且会因渠道、区域、门店和活动发生变化，因此：

- 商品主档不单独增加商品级“建议销售价”，销售价与 SKU/规格一起维护；
- 主档规格销售价用于形成标准定价和渠道商品首次定价，不等于所有渠道的最终生效价；
- 商品主档可选维护“标准成本/参考成本”，仅用于内部经营，不作为发布价格；
- 渠道商品库维护品牌级渠道售价；
- 商品模板维护区域或门店群价格差异；
- 门店渠道商品维护最终门店价格或临时经营调整；
- 新建渠道商品时，将主档规格销售价复制为渠道规格售价初始值；
- 渠道商品保存后形成独立数据，主档后续调整规格销售价不自动覆盖既有渠道售价。

### 1.4 渠道商品不是主档的完整复制

最终有效值按字段类型计算：

```text
强主档字段 = 始终读取商品主档

可覆盖继承字段 = 无渠道覆盖时持续读取商品主档
               主动独立设置后读取渠道覆盖值

渠道自有字段 = 读取渠道商品库公共售卖资料
             或具体渠道扩展资料

门店最终值 = 商品主档
           + 渠道商品
           + 具体渠道扩展
           + 商品模板
           + 门店本次调整
```

渠道商品只保存引用关系、渠道自有字段和发生差异的覆盖值，不复制一份完整主档。

## 2. 字段归属判定规则

判断一个字段应该放在哪里，统一按以下顺序执行：

| 判断问题 | 是 | 否 |
|---|---|---|
| 字段是否决定商品或 SKU 的统一身份、结构、内部识别？ | 放商品主档 | 继续判断 |
| 字段是否是客观事实，原则上不应因售卖渠道而改变？ | 放商品主档，作为强主档字段 | 继续判断 |
| 字段是否会因渠道团队、渠道定位或营销表达发生变化？ | 放渠道商品库 | 继续判断 |
| 字段是否只适用于一个具体渠道或平台？ | 放具体渠道扩展资料 | 继续判断 |
| 字段是否由平台接口产生或回传？ | 放平台执行状态，不作为商品资料编辑字段 | 继续判断 |
| 字段是否因区域、门店群或门店不同而变化？ | 放商品模板或门店渠道商品 | 不应新增到商品主档 |

### 2.1 四种字段继承类型

| 类型 | 定义 | 主档变化后的处理 | 示例 |
|---|---|---|---|
| M1 强主档字段 | 渠道不能修改，只能引用 | 所有渠道立即读取新值；已发布商品进入待更新提示 | 商品主档 ID、SKU ID、商品类型、商品类目、后台分类、前台分类定义、规格结构 |
| M2 主档默认、渠道可覆盖 | 默认不保存重复值，读取主档；仅主动独立设置时保存覆盖 | 未覆盖渠道继续跟随；已覆盖渠道保留覆盖，恢复跟随即删除覆盖 | 商品展示名称、前台分类归属、渠道商品主图、规格展示图 |
| C1 渠道商品字段 | 渠道天然拥有的售卖配置，部分字段可由主档提供初始值 | 不受主档变化影响 | 规格销售价、售卖时间、包装费、做法/加料/套餐售卖配置 |
| C2 渠道专属字段 | 只属于某个具体渠道 | 按该渠道能力版本校验 | 美团商品类目、淘宝商品特色、抖音提审资料 |

### 2.2 不允许自由覆盖的事实字段

以下字段即使平台允许填写，也不应让渠道团队自由改成与主档矛盾的数据：

- 商品和 SKU 身份；
- 商品类型、标准商品/套餐商品结构；
- 规格数量及规格身份；
- 是否称重、计量单位；
- 商品标准类目；
- 原料、配方、营养成分、生产地等客观事实；
- 商家商品标识、条码、SKU 编码；
- 税务分类等需要统一口径的内部资料。

如某渠道销售的商品事实确实不同，应新建主档或新建 SKU，而不是通过渠道覆盖伪装成同一商品。

## 3. 商品主档字段清单

### 3.1 商品身份与内部管理

| 字段 | 字段性质 | 是否必填 | 渠道能否修改 | 说明 |
|---|---|---:|---:|---|
| 商品主档 ID | M1 | 是，系统生成 | 否 | 全局统一商品身份 |
| 商品类型 | M1 | 是 | 否 | 标准商品、套餐商品等 |
| 商品标准名称 | M2 | 是 | 可维护渠道展示名称 | 用于内部识别和默认继承，不等于最终前台名称 |
| 数字助记码 | M1 | 否 | 否 | 用于内部检索、收银辅助 |
| 后台分类 | M1 | 否 | 否 | 内部经营管理和统计分类 |
| 商品类目 | M1 | 建议必填 | 否 | 决定类目字段、结构校验和平台类目映射候选 |
| 计量单位 | M1 | 条件必填 | 否 | 商品统一计量口径 |
| 是否称重商品 | M1 | 是 | 否 | 会影响 SKU 结构和 POS 售卖方式 |
| 内部备注 | M1 | 否 | 否 | 不发布到售卖渠道 |
| 统计标签 | M1 | 否 | 否 | 统一报表归集口径 |
| 主档状态 | M1 | 是 | 否 | 草稿、启用、停用、归档 |

### 3.2 商品标准素材与事实资料

| 字段 | 字段性质 | 是否必填 | 渠道能否修改 | 说明 |
|---|---|---:|---:|---|
| 商品识别图片/标准素材图 | M2 | 建议填写 | 可维护渠道展示图 | 用于主档识别、默认继承和素材复用，不直接等于渠道主图 |
| 标准成本/参考成本 | M1 | 否 | 原则上否 | 内部经营字段，不向渠道发布；区域成本差异由其他成本域承接 |
| 税务分类/开票项目 | M1 | 条件必填 | 否 | 统一财税归类；渠道实际税率由对应业务规则计算 |

配方和营养成分仍是商品中心内的重要业务资料，但由配方管理、营养成分页面按商品或 SKU 身份维护关系，不在商品主档编辑表单重复设置“配方引用”和“营养成分引用”。

### 3.3 SKU 与规格结构

| 字段 | 字段性质 | 是否必填 | 渠道能否修改 | 说明 |
|---|---|---:|---:|---|
| SKU ID | M1 | 是，系统生成 | 否 | 订单、库存、映射和统计的统一识别 |
| 规格模式 | M1 | 是 | 否 | 统一规格、多规格 |
| 规格名称/规格值 | M1 | 是 | 结构否；可管理渠道启用子集 | 规格身份、标准名称、数量和层级不能由渠道修改；渠道禁用规格值时，所有包含该值的 SKU 均不可售 |
| 规格销售价 | C1（主档提供初始值） | 是 | 可维护渠道规格售价 | 创建渠道商品时复制，之后由渠道商品独立维护，不需要品牌额外授权 |
| 商品条码 | M1 | 否 | 否 | SKU 统一条码 |
| 商品标识 | M1 | 否 | 否 | SKU 级商家标识 |
| 商品规格码 | M1 | 否 | 否 | SKU 编码 |
| 商品编码 | M1 | 否 | 否 | 内部或外部商品编码 |
| 商品分量及单位 | M1 | 否 | 否 | SKU 客观分量 |
| 规格识别图片 | M2 | 否 | 可维护渠道规格图 | 标准素材，可作为渠道默认图片 |
| 规格标准成本 | M1 | 否 | 原则上否 | 内部经营字段 |

不进入主档的规格字段：规格市场价、渠道库存策略/库存值、计划库存、包装费、包装标识和渠道规格值启用状态。SKU 可售结果由其包含的全部规格值状态计算，不另设可绕过规格值的 SKU 启停开关。

### 3.4 做法、加料与套餐的拆分原则

这些模块不能整体归为主档，也不能整体归为渠道商品，需拆分“结构”和“售卖配置”。

| 模块 | 商品主档维护 | 渠道商品库维护 |
|---|---|---|
| 做法 | 可用做法集合、做法身份、做法编码、标准名称、标准备注 | 启用子集、排序、默认值、必选规则、做法加价、提示文案 |
| 加料 | 可用加料集合、加料商品身份、加料编码、基础关联关系 | 启用子集、加料价格、规格加价、起购限购、必选、状态、未点提示、渠道排序 |
| 套餐 | 套餐商品身份、标准分组及候选商品关系 | 渠道有效分组、可选范围、必选数量、最大选择数、组内加价、计价类型、包装费收取方式、展示价格、随心配价格样式及渠道售卖规则 |

设计约束：

- 渠道只能从主档已定义的候选范围中启用、停用或调整售卖规则；
- 渠道需要增加主档不存在的做法、加料或套餐组成时，应先补充主档关系；
- 平台结构不支持原结构时，由平台适配规则做转换，不反向污染主档结构。
- 渠道商品不允许新增、删除、改名、拆分或合并规格；规格身份与 SKU 结构只由商品主档维护。
- 商品首次加入渠道商品库时，做法和加料按主档已关联范围初始化。
- 渠道可以从初始化范围中减少、停用或重新加入做法和加料，但不能从全局做法库、全局加料库直接选择主档未关联项。
- 主档新增做法或加料后只进入渠道“可添加项”，不自动启用；主档移除已被渠道使用的关系时进入待处理状态并阻止发布。
- 因此渠道做法、加料不是与主档平行的第二套结构，而是“主档允许集合上的渠道售卖子集”；配方、成本卡和供应链关系继续引用主档结构。

## 4. 渠道商品库字段清单

### 4.1 渠道分组共享售卖资料

以下字段默认可在一个渠道商品库分组内共享，并允许具体渠道按能力再覆盖：

| 字段 | 主档默认值 | 允许具体渠道覆盖 | 适用范围 | 说明 |
|---|---|---:|---|---|
| 渠道展示名称 | 商品标准名称 | 是 | 全渠道 | 不修改主档标准名称 |
| 渠道商品别名 | 无 | 是 | 全渠道 | 面向渠道搜索或展示 |
| 渠道商品主图 | 商品识别图片 | 是 | 全渠道 | 渠道实际发布图片 |
| 规格标准名称 | 规格标准名称 | 否 | 全渠道 | 渠道只读；平台字数或格式差异由适配层转换，不形成业务侧别名 |
| 规格展示图片 | 规格识别图片 | 是 | 支持规格图的渠道 | 按渠道能力决定是否发布 |
| 列表页简述 | 无 | 是 | 小程序、在线点等 | 营销展示字段 |
| 详情页描述 | 无 | 是 | 支持详情页的渠道 | 富文本需按渠道转换 |
| 商品视频 | 无 | 是 | 支持视频的渠道 | 渠道不支持时不发布 |
| 描述标签/点单标签 | 无 | 是 | 支持标签的渠道 | 不同渠道选项可能不同 |
| 商品角标 | 无 | 是 | 支持角标的渠道 | 渠道营销字段 |
| 品牌自定义属性 | 无 | 是 | 按品牌配置和渠道能力 | 用于渠道展示、筛选或营销扩展，不进入商品主档 |
| 基础售价 | 主档统一规格销售价（仅首次复制） | 是 | 统一规格商品 | 渠道商品保存后形成独立值 |
| 规格销售价 | 主档对应规格销售价（仅首次复制） | 是 | 多规格商品 | 渠道商品保存后形成独立规格价格 |
| 市场价/划线价 | 无 | 是 | 支持划线价的渠道 | 受平台规则限制 |
| 渠道售卖状态 | 无 | 是 | 全渠道 | 未发布、可售、停用等品牌级状态 |
| 售卖时间 | 无 | 是 | 全渠道 | 品牌级默认售卖时段 |
| 起购/限购 | 无 | 是 | 支持的渠道 | 具体平台可能使用不同字段 |
| 售卖方式 | 无 | 是 | 全渠道 | 正常售卖、仅套餐售卖等 |
| 做法售卖配置 | 主档候选关系 | 是 | 支持做法的渠道 | 启用、排序、加价、默认、必选 |
| 加料售卖配置 | 主档候选关系 | 是 | 支持加料的渠道 | 启用、排序、价格和选择规则 |
| 套餐售卖配置 | 主档标准结构 | 是 | 支持套餐的渠道 | 渠道有效结构、选择规则、计价类型、包装费收取方式、展示价格及随心配价格样式 |

### 4.2 应按具体渠道存储的通用字段

这些字段虽然不是某一家平台独有，但不能只在渠道分组层保存一个值：

| 字段 | 原因 | 存储粒度 |
|---|---|---|
| 前台分类 | 商品主档统一维护分类定义与默认归属；渠道商品库可覆盖本库归属，小程序、POS、三方渠道及营销、卡券等下游按其业务范围消费最终有效值 | 商品主档定义与默认值 + 渠道商品库覆盖值 |
| 平台类目 | 各三方平台拥有独立类目体系，需要与企迈商品类目/前台分类建立映射 | 渠道商品 + 具体平台 |
| 渠道销售价覆盖 | 同组渠道可能采用不同定价 | 渠道商品 + 具体渠道 |
| 渠道图片覆盖 | 平台图片尺寸、内容规范不同 | 渠道商品 + 具体渠道 |
| 渠道售卖时间 | 堂食、外卖和在线点时段可能不同 | 渠道商品 + 具体渠道 |
| 包装费与包装标识 | 到店外带、外卖配送规则不同 | 渠道商品 + 具体渠道/规格 |
| 库存策略 | 渠道可能共享库存或独立库存 | 渠道商品 + 具体渠道；实际库存落门店 |
| 上下架默认策略 | 各渠道可售范围不同 | 渠道商品 + 具体渠道 |
| 会员、积分规则 | 主要适用于自营渠道且渠道能力不同 | 渠道商品 + 具体渠道 |
| 税率与开票展示 | 渠道业务规则可能不同 | 渠道商品 + 具体渠道 |
| 做法、加料启用子集 | 不同渠道支持范围不同 | 渠道商品 + 具体渠道 |
| 套餐转换规则 | 平台套餐模型不同 | 渠道商品 + 具体渠道 |

### 4.3 库存字段边界

渠道商品库不保存门店实时库存，只保存品牌级策略或默认值：

| 数据 | 归属 |
|---|---|
| 是否启用库存、共享/独立库存策略 | 品牌配置或渠道商品 |
| 新店初始库存、计划库存规则 | 渠道商品或模板 |
| 区域、门店群默认库存 | 商品模板 |
| 门店实时库存、沽清数量 | 门店渠道商品/库存域 |
| 平台库存同步结果 | 平台服务执行状态 |

### 6.3 抖音在线点审核状态边界

当前已知只有抖音在线点品牌商品库需要审核，因此：

- 只有渠道商品适用渠道包含抖音在线点时，才展示“抖音审核状态”；
- 审核状态、失败原因、平台商品 ID 由平台服务回传，商品中心只读展示；
- 其他渠道不统一增加空泛的“平台状态”列；
- 商品加入包含抖音在线点的渠道商品库并补齐必填资料后，可按产品策略自动提交品牌商品库审核；
- 资料未完整时保留“待完善”，不提交；
- 审核失败后在操作区提供“修改资料”和“重新提交审核”，不把长说明常驻在列表中；
- 后续若其他平台增加品牌商品审核，通过渠道能力配置开启，不修改核心商品模型。

### 6.4 平台自行维护资料的渠道

某三方渠道配置为“平台自行维护资料”时，先判断企迈是否参与接单、上下架、库存或沽清：

- 企迈参与任一经营能力时必须进入渠道商品库分组；企迈完全不参与时才不进入；
- 商品中心不展示该平台专属字段；
- 平台商品名称、价格、图片等仍由平台维护；
- 商品中心从所属渠道商品库生成企迈侧渠道/门店渠道商品所需资料；
- 映射、平台商品 ID、接单识别和平台执行状态由平台服务负责；
- 不应因为平台自行维护资料的渠道存在，就要求主档或其他渠道商品填写该平台资料字段。

## 8. 渠道商品库编辑页的信息架构

当一个渠道商品库分组包含多个渠道时，建议页面按以下结构组织：

```text
渠道商品编辑
├── 关联主档
│   └── 主档身份、SKU、类目、规格结构、事实资料（只读）
├── 公共售卖资料
│   └── 分组默认名称、图片、售价、描述、SKU/做法/加料启停状态及套餐售卖配置
├── 渠道配置
│   ├── POS
│   ├── 小程序外卖
│   ├── 美团外卖
│   └── 淘宝闪购
└── 发布与异常
    └── 各渠道完整度、待发布、发布失败；抖音等按能力展示审核状态
```

页面规则：

- 不提供“是否持续继承整份主档”的总开关；
- M2 名称和图片默认继续读取主档，只有主动独立设置后才成为渠道覆盖值；C1 售价等字段创建时初始化，之后成为渠道商品独立售卖值；
- 具体渠道页只展示当前渠道支持或要求的字段；
- 同语义字段在不同渠道规则不一致时，分别保存渠道值；
- 具体渠道差异未配置时使用渠道商品库公共值；M2 公共值未覆盖时继续读取主档，C1 字段不在运行时回读主档；
- 渠道分组包含小程序堂食或小程序外卖时，渠道商品主图强制展示且必填；缺失时不可保存为可发布状态，也不可创建小程序发布任务；
- SKU、做法、加料只可在主档候选范围内启用或禁用，不允许渠道新增、删除、改名或改变规格结构；
- 不在列表常驻展示复杂底层逻辑，只在字段来源、冲突或操作时提示；
- 本期不开放“渠道商品常用字段设置”，渠道表单使用产品预置的字段分组、默认展开和显隐规则；该能力后续需要真实类目差异和使用频率验证后再评估。
- 本期不开放“渠道字段覆盖规则”。M1身份、事实与结构字段保持主档权威；已确认允许独立维护的M2字段按产品固定白名单执行，暂不允许商家自定义放开范围。

## 9. 类目与渠道字段能力配置

### 9.1 字段能力不能继续写死在页面

未来字段渲染应由以下维度共同决定：

```text
品牌
× 商品类型
× 商品类目
× 数据层级
× 渠道
× 平台能力版本
```

### 9.2 字段定义至少包含

| 配置项 | 说明 |
|---|---|
| fieldCode | 稳定字段编码 |
| fieldName | 字段名称 |
| ownerLayer | MASTER / CHANNEL_COMMON / CHANNEL_EXTENSION / STORE / PLATFORM_RUNTIME |
| channelCode | 适用渠道；公共字段可为空 |
| productType | 标准商品、套餐商品等 |
| categoryScope | 适用商品类目 |
| controlType | 输入、选择、级联、图片、开关、规则编辑器等 |
| requiredRule | 必填条件表达式 |
| optionSource | 固定选项、商品中心字典或平台接口 |
| validationRule | 长度、范围、互斥、图片规格等 |
| inheritMode | 强继承、可覆盖、不继承 |
| publishMapping | 发布至平台时的字段映射 |
| capabilityVersion | 能力版本 |
| effectiveTime | 规则生效时间 |

### 9.3 表单渲染规则

- 商品主档页只读取 `ownerLayer=MASTER` 的字段；
- 渠道商品公共页读取 `CHANNEL_COMMON` 字段；
- 渠道页读取当前 `channelCode` 对应的 `CHANNEL_EXTENSION` 字段；
- 平台自行维护资料的渠道不渲染平台资料扩展字段，但企迈参与经营时仍渲染企迈侧商品所需公共字段；
- 分组包含多个渠道时，公共页展示公共字段，各渠道页分别展示渠道字段；
- 完整度按每个目标渠道单独计算，不能用一个总完整度掩盖单渠道缺失；
- 平台能力升级后重新校验，不直接删除历史字段和值。

## 10. 主档变更与渠道商品更新规则

| 主档变更 | 未覆盖渠道商品 | 已覆盖渠道商品 | 已发布商品 |
|---|---|---|---|
| 标准名称修改 | 自动读取新名称 | 保留渠道展示名称 | 标记目标渠道“有更新待发布” |
| 识别图片替换 | 自动读取新图片 | 保留渠道图片 | 校验图片是否仍满足平台规则 |
| 商品类目修改 | 自动更新引用 | 不允许渠道覆盖 | 重新计算渠道字段和平台类目映射风险 |
| 规格新增/删除 | 自动更新结构 | 不允许保留不存在的 SKU | 阻止直接删除已售 SKU，进入变更流程 |
| 规格标准名称修改 | 自动读取新名称 | 不允许覆盖 | 标记待发布；平台格式差异重新适配 |
| 条码/SKU 编码修改 | 自动更新引用 | 不允许覆盖 | 触发映射和订单识别风险校验 |
| 做法/加料候选范围变化 | 更新候选关系 | 保留仍有效的渠道配置 | 已删除关系进入待处理 |
| 原料/生产地变化 | 自动读取新事实 | 不允许覆盖事实 | 涉及前台展示时提示重新发布 |

主档修改后的处理分为两类：

1. M1 身份与结构字段更新主档权威值，受影响渠道进入校验或待发布事项；
2. M2 首次复制字段不自动同步，既有渠道商品继续保留自身数据；
3. 新加入渠道商品库的商品按最新主档值初始化；
4. 强主档字段发生破坏性变化时阻止或进入专项变更流程。

## 11. 数据模型建议

| 对象 | 主要内容 |
|---|---|
| `GoodsMaster` | 商品身份、类目、计量、事实资料、标准素材 |
| `GoodsMasterSku` | SKU 身份、规格结构、条码和编码 |
| `MasterRelation` | 做法、加料、套餐、配方等标准关系 |
| `ChannelCatalog` | 渠道商品库及适用渠道分组 |
| `ChannelGoods` | 引用主档 SKU、公共售卖资料、版本和状态 |
| `ChannelGoodsOverride` | 对 M2 字段的渠道分组或具体渠道覆盖 |
| `ChannelGoodsExtension` | 按 channelCode 存储具体渠道字段 |
| `ChannelGoodsSnapshot` | 发布时固化的最终有效商品数据 |
| `PlatformExecutionState` | 平台商品 ID、发布、审核、失败和映射摘要 |

关键唯一性：

```text
同一渠道商品库内：
catalogId + masterSkuId 唯一

同一渠道商品的具体渠道扩展：
channelGoodsId + channelCode + capabilityVersion 唯一
```

## 12. 对现有 PRD 和原型的调整建议

### 12.1 P02 需要补充

- 增加本文的主档字段白名单；
- 将“名称、价格、图片都采用同一种继承方式”改为：
  - 名称和标准图片为 M2，无覆盖时持续读取主档，主动独立设置后保留覆盖值；
  - 规格销售价为 C1，只在创建渠道商品时由主档初始化，之后独立维护；
- 删除 `MASTER_CHANNEL_EXTENSION` 概念，主档不维护三方渠道扩展；
- 将 `CHANNEL_GOODS_EXTENSION` 明确为“按具体渠道存储”，不能只按渠道商品存一份 JSON；
- 增加渠道分组公共售卖资料与具体渠道覆盖的合并顺序；
- 增加做法、加料、套餐的结构层与售卖层拆分；
- 增加平台执行状态只读边界。

### 12.2 商品主档原型需要体现

- 只平铺展示主档字段，不保留销售属性、展示营销字段和三方渠道属性；
- 商品识别图片命名应与渠道商品主图区分；
- 不展示商品级商家商品标识、商品皮重、生产地、原料说明、配方引用和营养成分引用；
- 不展示商品级建议销售价、市场价、包装费、库存和空销售属性区块；前台分类作为主档共享字段展示并维护；
- 规格编辑中保留结构、身份、条码、编码、分量、标准素材和规格销售价；
- 做法、加料、套餐仅维护公共候选关系和标准结构。

### 12.3 渠道商品库原型需要体现

- 使用完整商品编辑框架，但字段来自渠道商品能力配置；
- 公共售卖资料和具体渠道资料分区；
- 规格售价不显示为持续“继承主档”，仅在首次加入渠道商品库时初始化；
- 生产地、原料说明作为渠道杯贴/打印资料维护；商品皮重仅对 POS 渠道展示；
- 根据渠道分组动态展示 POS、小程序、美团、淘宝闪购等渠道页；
- 渠道分组包含小程序堂食或小程序外卖时，商品主图必须显示为必填；缺少主图时阻止保存和创建小程序发布任务；
- 商品属性区域包含描述标签、点单标签、角标、系列商品和品牌自定义属性；自定义属性按适用渠道和字段能力动态显示；
- 规格、做法和加料仅展示主档候选对象及启用状态，不提供渠道侧新增、删除、改名和规格结构修改；
- 只有抖音等确有品牌审核能力的渠道展示审核状态；
- 发布状态、审核状态和映射状态均为平台服务回传摘要，不与可编辑资料混在一起。

## 13. 第一阶段建议范围

第一阶段不需要一次补齐所有平台字段，但必须先把底层归属设计正确：

1. 建立主档字段白名单和渠道商品字段白名单。
2. 建立 `ownerLayer`、`channelCode`、`inheritMode` 和 `capabilityVersion` 元数据。
3. 支持渠道商品公共售卖资料与按渠道扩展数据。
4. 支持 M1 强主档、M2 首次复制、C1 渠道自有、C2 渠道专属四种字段类型。
5. 美团外卖、淘宝闪购按现有截图字段占位。
6. 抖音在线点、美团在线点、美团拼好饭先建立渠道页和能力占位；京东外卖本期不对接、不展示渠道页，也不进入商品库分组和渠道配置。
7. 抖音在线点支持审核状态回传、失败原因和重新提交。
8. 发布快照必须记录每个字段的最终值、来源层级和能力版本。

不建议第一阶段采用“把现有商品表单全部复制到渠道商品库，再逐步隐藏”的方式。该方式会把价格、库存、主档结构和平台字段继续混在一起，后续很难治理主档变更、字段权限和平台能力升级。
