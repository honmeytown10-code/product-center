## 2. 本轮目的

本轮核心是重新设计商品中心 PC 后台的 UI 与交互，不是重新定义业务字段或推翻原全渠道业务方案。优化范围覆盖每个菜单页面、每个功能按钮、每个弹窗/抽屉，并尽量细化到字段显示、条件、校验、权限和状态。

## 3. 已确认决策

### 3.1 菜单与功能域

```text
商品工作台

商品资料
  商品管理 / 商品主档
  分类与属性
  配方与营养

渠道经营
  渠道商品
  渠道分类与属性（仅分渠道协作）
  商品模板
  销售规则
  商品推荐

发布与治理
  发布中心
  映射治理
  差异巡检

门店执行
  门店商品

配置
  商品设置
```

全渠道商品管理策略从独立菜单收敛到“商品设置”页内入口；这是低频配置入口合并，不改变其现有业务字段、校验、影响分析与保存语义。

开放接口按客户能力和权限显示，但仍属于全量优化范围。

### 3.2 页面不能一套模板到底

- 工作台是任务推进型页面。
- 商品列表是高密度对象管理页面。
- 渠道商品是渠道资料适配与协作页面。
- 发布中心是预检、确认、批次和异步结果页面。
- 映射与差异页面是风险发现、对照和治理闭环页面。
- 配置页面是低频、高风险、需要影响说明的策略页面。

共享的是 Console 2.0 外壳、视觉 Token、状态语言、批量反馈、权限和审计表达，而不是把所有页面做成相同布局。

### 3.3 工作台已确认项

- 当前任务型布局和整体风格可继续沿用。
- 左侧菜单和页面不展示可见滚动条，但仍允许正常滚动。
- 详情抽屉必须覆盖在列表上方，打开时列表宽度、列宽和工具栏位置保持不变。
- 抽屉开启后可使用遮罩或非阻塞覆盖方式；关闭后保持原筛选、选中项、滚动位置和批量状态。

任务的创建规则、负责人解析、SLA、升级、提醒和转交权限尚未确认，不得因原型演示而写死。推荐方向是“系统内置领域任务 + 可配置职责路由”，最终字段与配置入口仍待业务确认。

### 3.4 商品创建和业务字段保护

- 创建商品仍只有“标准商品”和“套餐商品”两种类型。
- 两种类型对应的可选类目、字段、联动和校验全部以原全渠道代码为准。
- 商品类目、商品主档、渠道商品的原字段不得因 UI 改版而改名、删减、合并或替换。
- 若某字段的 UI 表达需要优化，只允许改变分组、层级、控件、帮助信息、错误定位、交互容器和反馈方式；字段业务语义保持不变。

### 3.5 全渠道配置保护

现有全渠道配置的真实业务模型以 `WebOmnichannelSettings.tsx`、`omnichannel.ts` 和 `types.ts` 为准，包含：

- 组织协作方式：统一商品维护 / 按渠道职责协作。
- 三方渠道的商品资料维护位置：企迈管理 / 平台管理。
- 平台管理时企迈可参与的现有能力。
- 渠道商品库分组及一个渠道只能属于一个分组的约束。
- 门店连接要求的派生状态。
- 分组、未分组、切换维护位置和保存时的现有校验与联动。

UI 可优化信息层级、因果表达、影响预览、只读/可编辑区分、校验定位、未保存提醒和危险操作确认；不得自行添加负责人、SLA、巡检默认值、默认发布规则等未确认配置字段。

## 4. 已明确否决的做法

- 以“UI 优化”为名修改商品、类目、主档、渠道商品或配置字段。
- 用设计技能中的建议模型覆盖原全渠道代码中的真实业务字段。
- 创建商品时增加新的商品类型或更换两类商品各自的类目逻辑。
- 所有菜单页面使用同一信息结构。
- 抽屉打开后通过缩窄主内容区来给抽屉让位。
- 只完成少数代表页，遗漏分类与属性、渠道分类/属性、四类销售规则、门店分类/属性或开放接口。
- 只做正常态静态页面，不做按钮行为、弹窗、权限、错误和恢复。

## 5. 页面完成口径

每个页面/稳定页内视图需要同时完成：

1. 页面契约：角色、目标、对象、范围、上下游、策略联动。
2. 字段级规格：字段来源、显示条件、默认值、校验、权限、继承/覆盖。
3. 动作级规格：主按钮、次按钮、行操作、批量操作、更多菜单。
4. 容器级规格：弹窗、抽屉、向导、二次确认、未保存和失败恢复。
5. 状态矩阵：加载、空、错误、无权、部分成功、并发和异步。
6. 可操作原型：核心链路可点击并有真实反馈。
7. 视觉验收：1440px、长文案、关键列、滚动、遮罩和固定操作区。
