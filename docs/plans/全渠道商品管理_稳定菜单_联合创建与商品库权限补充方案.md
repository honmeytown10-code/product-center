# 全渠道商品管理：稳定菜单、联合创建与商品库权限补充方案

> 状态：已确认补充方案  
> 日期：2026-08-06  
> 适用范围：商品中心 PC 后台、全渠道商品管理策略、商品主档、渠道商品、权限与模式迁移  
> 说明：本文件补充并修正原方案中“统一管理隐藏渠道经营入口”“渠道商品只能选择已有主档”“菜单权限等于全部商品库权限”等不完整口径。

## 1. 决策结论

1. 统一管理和分渠道协作使用同一套菜单结构，始终保留“商品主档”“渠道商品”“渠道属性”；后台分类和前台分类的定义统一归商品主档“分类与属性”，渠道商品可覆盖当前商品库的前台分类归属。
2. 协作方式只改变渠道商品库数量、职责分工和处理流程：统一管理只有一个品牌默认商品库，分渠道协作可以有多个商品库。
3. 渠道商品页增加品牌级“商品创建方式”配置：
   - 仅选择已有商品主档；
   - 允许同时创建主档与渠道商品。
4. 两种协作模式都可使用“同时创建”；统一管理推荐开启，分渠道协作由品牌根据团队职责选择。
5. 同时创建不是新的商品对象。仍只允许“标准商品、套餐商品”两种类型，继续沿用各自原有类目、字段、默认值、联动和校验。
6. 渠道商品库是独立的数据权限范围。拥有“渠道商品”菜单权限，不代表可以查看或管理全部商品库。
7. 原型默认当前账号拥有全部商品库权限，不额外展示权限配置；正式需求、接口与验收必须实现权限规则。

## 2. 为什么保持菜单稳定

协作方式是组织如何分工，不是商品中心拥有哪些业务对象。无论一个团队还是多个团队管理，系统都存在：

- 商品主档：商品身份、商品类型、类目、SPU/SKU 结构、做法、加料、套餐结构等；
- 渠道商品：名称/图片覆盖、前台分类归属、售卖资料和按需出现的平台字段；前台分类默认继承商品主档并可按当前商品库覆盖，规格售价继承商品主档；
- 渠道商品库：一组渠道共用的品牌级渠道商品资料及其责任范围。

若切换模式就隐藏“渠道经营”，会造成入口位置、培训资料、权限配置、收藏链接和操作习惯整体变化，也会把底层对象差异错误表达成“统一模式没有渠道商品”。因此新方案采用稳定菜单，模式差异只在页面内部体现。

| 能力 | 统一管理 | 分渠道协作 |
| --- | --- | --- |
| 商品主档菜单 | 展示 | 展示 |
| 渠道商品菜单 | 展示 | 展示 |
| 渠道属性页内入口 | 展示 | 展示 |
| 渠道商品库数量 | 1 个品牌默认商品库 | 1 个或多个业务商品库 |
| 商品库切换 | 不展示无意义切换 | 只展示用户获权商品库 |
| 默认创建建议 | 允许同时创建 | 仅选择已有主档，可按品牌开启同时创建 |
| 资料责任 | 同一团队可同时承担两类资料 | 商品团队与渠道团队可分工 |

## 3. 渠道商品库的商品创建方式

### 3.1 配置项

- 配置层级：品牌级。
- 配置入口：商品设置 → 全渠道商品管理策略 → 商品资料怎么分工与创建。
- 配置名称：渠道商品库的商品创建方式。
- 选项 A：仅选择已有商品主档。
- 选项 B：允许同时创建主档与渠道商品。
- 统一管理切换时推荐自动选择选项 B；切回分渠道协作后保留现有选择，由品牌管理员决定是否关闭。

暂不做每个商品库分别配置，避免不同商品库出现难以理解的创建入口差异。若后续客户证据证明各渠道团队差异显著，再扩展为品牌默认策略加商品库例外。

### 3.2 交互入口

渠道商品页顶部始终明确当前商品库：

- 未开启同时创建：显示“选择已有主档”；
- 已开启同时创建：显示“选择已有主档”和主按钮“新建商品”；
- 统一管理也保留“选择已有主档”。默认商品库已承接的主档在选择器中标记“已生成渠道商品”且不可重复选择；迁移、导入或异常恢复产生的仅主档商品仍可从该入口补建渠道商品；
- “新建商品”下只有“新建标准商品”“新建套餐商品”，选择后进入对应原有类目选择器。

### 3.3 联合创建流程

```text
当前渠道商品库 → 新建商品 → 选择标准商品/套餐商品
→ 选择该类型原有可选类目
→ 填写主档资料、主档商品结构和渠道商品属性
→ 查重与权限校验 → 一次提交
→ 创建商品主档 → 按继承规则生成当前商品库的渠道商品并建立引用
→ 返回当前商品库，可继续发布或加入销售规则
```

联合创建采用“共用资料一次填写、渠道属性同页维护”，不在创建页并排展示两套相同字段，也不把渠道资料推迟到创建后：

- 主档资料区：商品身份、商品类型、后台类目、SPU/SKU、规格结构、做法、加料、套餐结构等现有主档字段；
- 共用字段继承：渠道名称取主档名称，渠道图片取主档主图，规格/做法/加料完整继承主档；创建页不重复展示这些输入项；
- 主档资料区：后台分类、前台分类与其他共用资料一次填写；前台分类随主档供全部渠道和营销、卡券等下游使用；
- 渠道商品属性区：列表/详情展示资料、描述标签、角标、起购限购、分时段销售、售卖方式和渠道补充资料可在联合创建时维护；前台分类在创建时取主档默认值且不重复填写，创建后可按当前商品库覆盖，规格售价直接继承主档；
- 渠道专属属性区：仅当当前商品库包含需要企迈维护平台资料的三方渠道时出现相应字段；平台维护资料但使用企迈接单或上下架/库存的渠道，仍归属商品库并下发企迈侧门店渠道商品用于映射，但不要求维护平台权威字段。
- 创建完成后仍可通过独立“维护渠道资料”入口继续调整渠道差异；该入口是后续维护方式，不是联合创建的必经第二步。

上述规则只改变录入方式，不合并底层对象。主档字段与渠道字段仍分别存储、分别鉴权，服务端需在联合创建请求中显式落入渠道继承值与继承状态。

### 3.4 原子性与失败恢复

- 提交前统一校验两部分资料，避免先创建主档后才发现渠道资料无法保存。
- 后端采用一个业务请求或可恢复事务编排；主档成功、渠道商品失败时不得向用户伪装全部成功。
- 若无法保证数据库原子事务，必须记录编排任务和幂等键，并提供“继续创建渠道商品”或“撤销未引用主档”的恢复动作。
- 重复点击不能生成两个主档；重复请求返回首次结果。
- 命中疑似重复主档时优先展示匹配结果并引导“选择已有主档”，用户确认不存在重复后才允许继续。

### 3.5 创建与编辑入口边界

联合创建只解决一次录入和一次提交，不延伸为联合编辑。渠道商品创建完成后，列表默认操作写成“维护渠道资料”，只进入当前商品库的渠道商品编辑页。不得提供“维护主档与渠道”混合入口。

- `existing_master_only`：顶部“从商品主档添加”是页面唯一主操作，使用主色按钮；列表不展示任何主档编辑入口。
- `create_master_and_channel`：顶部“新建商品”是主操作，“选择已有主档”是次操作；若当前用户同时拥有 `product_master.edit`，列表可展示独立的“编辑商品主档”，进入商品主档编辑页。
- 创建方式只决定渠道商品库能否发起主档创建，不授予主档编辑权限；正式产品始终以 `product_master.edit` 决定主档编辑入口。

| 内容 | 主档区 | 当前渠道商品区 |
| --- | --- | --- |
| 商品名称 | 创建页只填写“主档商品名称”，用于统一身份与默认名称 | 创建时自动取主档名称且不重复展示；创建后可在“维护渠道资料”中改为独立名称 |
| 名称联动 | 修改主档名称只更新仍处于“跟随主档”的渠道商品 | 独立名称不回写主档；支持“恢复跟随主档” |
| 规格/SKU | 新增、删除、改名、编码、组合结构与规格售价 | 只能启停主档已存在的规格并维护渠道库存等销售值；售价继承主档 |
| 做法/加料 | 维护候选集合、编码和关系 | 只能缩小启用子集及维护渠道加价等销售值 |
| 图片、前台分类、描述、平台字段 | 图片和前台分类默认继承，其他字段按归属维护 | 渠道覆盖仅影响当前商品库及其下发渠道；前台分类定义仍由主档统一维护 |
| 规格售价 | 作为商品统一基础售价维护 | 渠道商品直接继承，不提供联合创建时的覆盖入口 |

修改主档结构必须在独立主档编辑页展示影响范围，并对需要渠道负责人确认的商品生成“渠道确认”任务。渠道编辑页只提交渠道字段；主档编辑页只提交主档字段，任何入口不得因为用户拥有渠道商品菜单权限而赋予主档编辑能力。

## 4. 渠道商品库权限模型

### 4.1 三层权限

| 层级 | 回答的问题 | 示例 |
| --- | --- | --- |
| 页面权限 | 是否能进入这个页面 | 渠道商品查看、商品主档查看、全渠道策略配置 |
| 固定渠道数据范围 | 能管理哪些稳定渠道资源 | POS、小程序堂食、小程序外卖、美团外卖等 channelId |
| 动态商品库范围 | 当前分组下能看到哪些业务商品库 | 由固定渠道权限与当前渠道—商品库关系实时推导 |
| 操作权限 | 在获权商品库能做什么 | 选择已有主档、联合创建、编辑、移出、导入、导出、发布 |

用户拥有渠道商品菜单权限但按固定渠道权限无法推导出任何商品库时，页面展示“暂无任何渠道商品库权限，请联系品牌管理员”，不得展示空列表，也不得泄露商品库名称和数量。分组调整只重新推导商品库范围，不自动增加用户的固定渠道权限；编辑商品库公共资料还需覆盖该库全部渠道或拥有显式共享资料权限。

### 4.2 建议权限动作

- `channel_product.view`：进入渠道商品页；
- `channel_catalog.scope`：可访问商品库 ID 集合；
- `channel_product.add_existing`：选择已有主档加入当前商品库；
- `product_master.create`：创建商品主档；
- `channel_product.create`：在当前商品库创建渠道商品；
- `channel_product.edit`、`remove`、`import`、`export`、`publish`：对应操作；
- `channel_catalog.manage`：新建、改名、删除、调整渠道归属；
- `channel_catalog.grant`：分配商品库权限，和普通商品库管理分开控制。

联合创建需要同时满足：`product_master.create` + 当前商品库范围 + `channel_product.create`。只有渠道商品权限的人员继续使用“选择已有主档”；若业务需要，可提交主档创建申请给商品团队，不得绕过主档权限直接落库。

### 4.3 数据隔离

- 商品库切换器只显示获权商品库；默认选择最近使用的可访问商品库。
- 列表、搜索、分类计数、工作台待办、导入导出、发布预检与日志只返回获权范围。
- 导入文件包含无权商品库或商品时整批阻止或给出逐行无权明细，不得静默写入。
- 跨商品库批量操作必须按有权范围拆分并显示无权数量；不能因前端隐藏就省略服务端鉴权。
- 商品库重命名沿用原商品库 ID，权限不变；删除、合并或迁移需处理授权、待办、发布任务和审计。

### 4.4 模式切换权限迁移

分渠道协作切换为统一管理时，多个商品库合并为一个默认商品库，可能把原来彼此隔离的数据放到同一范围。为避免越权：

1. 切换前展示各商品库现有角色与用户；
2. 原仅拥有部分商品库权限的用户不自动获得默认商品库全量权限；
3. 品牌管理员必须明确指定默认商品库的新查看、维护、创建和发布人员；
4. 未确认的新范围默认不授权；品牌管理员等全局管理角色按既有规则保留全量权限；
5. 保存原商品库和权限快照，切回分渠道协作时优先恢复；统一期间新增人员和商品进入待分配清单。

## 5. 原型调整范围

- 左侧菜单：两个协作模式均显示商品主档、渠道商品；渠道属性作为渠道经营页内稳定入口，商品分类统一在商品资料“分类与属性”维护。
- 商品主档：继续只维护主档职责，不因统一管理改名或混入渠道字段。
- 渠道商品：统一管理显示一个默认商品库；分渠道协作显示多个商品库。
- 全渠道策略：增加渠道商品库创建方式；模式切换影响说明不再提示菜单出现或消失。
- 联合创建：保留标准/套餐和原类目选择；表单展示主档资料、主档结构、渠道展示/售卖/补充资料和渠道专属属性，共用字段按继承规则自动生成且不重复录入。
- 权限：原型默认全部商品库可见，不制作权限配置页面。

## 6. 验收要点

- 任意协作模式切换后左侧菜单项与顺序不变化。
- 统一管理渠道商品页只出现一个默认商品库。
- 分渠道协作开启联合创建后，可从当前商品库创建标准或套餐商品，并仍先选择对应原有类目。
- 一次保存后商品主档列表和当前渠道商品库均可查询到该商品，渠道商品引用同一主档 ID/SKU 身份。
- 联合创建页不重复要求渠道名称、渠道图片、规格售价和继承结构；前台分类在主档资料区填写一次，渠道展示资料及售卖属性在渠道区维护，保存后的渠道商品获得正确继承值、渠道属性和继承状态。
- 关闭联合创建后渠道商品页不显示新建入口，只允许选择已有主档。
- 无商品库范围、部分范围、无主档创建权限、无当前商品库创建权限、跨库批量和模式迁移均有明确需求与服务端鉴权。
