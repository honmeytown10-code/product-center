# 自助餐菜单 PC 后台交互原型

更新日期：2026-08-20
原型入口：商品中心 → 渠道经营 → 销售规则 → 自助餐菜单
实现文件：`components/web/WebBuffetMenuManager.tsx`

## 1. 页面契约

```yaml
page:
  productArea: 商品运营
  domain: 自助餐菜单
  type: list + form + detail-drawer + selector
  accountView: 品牌
  primaryTask: 关联自助餐门票、菜单商品与适用门店，生成扫码/PAD点餐使用的餐标菜单
  objects: [自助餐门票商品, 自助餐菜单, 商品/SPU, 门店]
  globalScope:
    organization: hidden
    store: required-in-form
    channel: 扫码点餐与PAD点餐（原型固定）
  primaryAction: 创建自助餐菜单
  states: [loading, success, first-empty, filtered-empty, error, no-permission, submitting]
  risks: [同餐标同门店重复命中, 餐标未覆盖门店, 菜单商品未覆盖门店, 启停影响]
```

### 目标角色与高频任务

- 品牌商品/运营负责人：为成人票、儿童票、午市票、晚市票等餐标维护可点菜单。
- 区域运营：为同一餐标按不同门店范围配置差异菜单。
- 门店运营：查看当前门店餐标命中的菜单；首期不在本页直接改品牌菜单。

高频任务：创建菜单、调整不限量/限量商品、调整适用门店、处理餐标与门店冲突、启停菜单。付费商品首期屏蔽，不提供配置入口。

### 功能归属

自助餐菜单属于“渠道经营 → 销售规则”的独立页内视图：

- 自助餐门票继续作为商品主档对象维护；选择弹窗同时提供精简创建入口，创建成功后回到菜单上下文并自动选中该门票。
- 自助餐菜单是餐标、可点商品结构和门店范围的经营规则，不修改商品/SPU 身份。
- 门店商品仍负责商品在具体门店的上下架、库存、沽清等经营状态；菜单保存不校验所选商品是否覆盖全部门店，点餐端仅展示当前门店实际存在且可售的菜单商品。
- 扫码点餐与 PAD 点餐按“门店 + 已购餐标”读取菜单，本页不承担点餐端页面装修。

## 2. 对象与关系

```text
自助餐门票商品（餐标） 1 ─── n 自助餐菜单 n ─── n 门店
                              │
                              ├── 不限量商品（SPU）
                              └── 限量商品（SPU，每人限量）
```

- 一个菜单可关联多张门票，前提是这些门票在相同门店看到完全相同的菜单内容。
- 一张门票可关联多个菜单，用于不同门店维护差异菜单。
- 菜单行项目关联稳定商品/SPU ID；选择时复用系统已有的商品选择组件，并以一行一个 SPU 的方式返回商品 ID。
- 同一 SPU 在同一菜单中只能属于一个权益分组；不限量与限量之间在选择和保存时均校验不可重复。商品下当前有效规格由点餐端结合门店商品实际状态展示。

## 3. 冲突与保存规则

### 已在原型采用的建议口径

同一张自助餐门票在同一家门店只能命中一个已启用菜单。判断键为：

```text
ticketProductId + storeId + enabled
```

因此：

- 同餐标、不同门店：允许。
- 不同餐标、同门店：允许。
- 同餐标、同门店、多个已启用菜单：禁止。
- 菜单仅有已启用、已停用两种状态，不提供草稿状态；已停用菜单可与已启用菜单暂时存在餐标/门店重叠，保存并启用、编辑已启用菜单和重新启用必须通过唯一性校验。
- 停用菜单不自动回滚已下单商品；后续扫码/PAD 请求不再命中该菜单。

### 关联完整性校验

启用前同时检查：

1. 菜单名称、至少一张餐标、至少一个菜单商品；适用范围选择“指定门店”时至少选择一家门店。
2. 自助餐门票商品处于可用状态，并覆盖全部所选门店。
3. 不限量商品与限量商品的 SPU 不得重复；选择与保存时双重校验。
4. 同餐标、同门店没有其他已启用菜单。
5. 当前账号拥有全部所选门店的数据范围与菜单维护权限。

## 4. 页面与交互

### 列表

筛选：关键词（菜单名称/编号/餐标）、餐标、适用门店、状态；点击“查询”后更新结果，重置同时清空查询条件。
列：菜单名称/编号、关联门票、不限量/限量商品数量、适用门店、状态、最近更新、操作。
主操作：创建自助餐菜单。
行操作：查看、编辑、复制、删除；启停通过状态开关与二次确认完成。删除已停用菜单需二次确认并说明餐标、门店、商品数量及不可恢复后果；已启用菜单必须先停用，不能直接删除。

关联多张门票时，列表首行展示第一张门票名称，次行展示“共 N 张餐标”；完整门票名称通过单元格 Tooltip 和详情抽屉查看，不在表格中平铺多个长标签。适用范围为全部门店时，使用独立“全部门店”范围标签并展示“当前 N 家”，强调这是随品牌门店变化的动态全量范围；指定门店则展示第一家门店及“指定 N 家”。

保存、保存并启用或删除完成后直接刷新列表结果，不在筛选区上方常驻成功提示条。

复制菜单时只复制商品结构，主动清空餐标和适用门店，由用户重新选择。

### 创建/编辑三步页

1. 餐标：菜单名称；通过选择弹窗手动选择已启用的自助餐门票，新建和复制均不默认带入；选择弹窗和已选列表只读展示门票适用人数、售价。选择弹窗提供“新增自助餐门票”，只填写商品名称、前台分类、商品售价、适用人数、是否收取押金；后台类目固定为“自助餐门票”且不展示，保存成功后自动勾选新门票。
2. 菜单商品：当前只展示不限量、限量两个并列 Tab，付费商品能力暂时屏蔽。页面按钮统一使用“添加商品”，配置列表按 SPU 展示，不展示规格列。复用系统 `WebProductSelectorDialog` 商品选择组件并启用 SPU 模式：一行一个商品，隐藏 SKUID 查询和列表列，底层保存稳定商品 ID。限量商品只填写每人限量份数，不提供按桌限制。
3. 适用门店：先选择“全部门店”或“指定门店”。选择全部门店时不出现门店选择器，系统自动展开为当前品牌全部门店；选择指定门店时才显示统一门店选择器并要求至少选择一家。点击保存或保存并启用时执行餐标唯一性与门票覆盖校验；不校验菜单商品是否覆盖门店。

不再设置独立“校验确认”步骤。第一步点击下一步时校验菜单名称和餐标，第二步点击下一步时校验菜单商品及不限量/限量重复，第三步点击保存时校验适用门店、餐标门店覆盖和启用冲突，并将用户定位到对应错误位置。

“保存”保持编辑前状态，新建菜单保存为已停用；“保存并启用”保存为已启用。已停用菜单允许暂存餐标/门店重叠，但启用前必须处理；商品在某门店不存在或不可售时不阻塞保存，由点餐端在该门店隐藏。复杂配置使用独立页面，选择商品/门店使用弹窗，详情使用覆盖式抽屉且不挤压列表。

### 详情抽屉

展示菜单身份、状态、关联餐标及其适用人数/售价、不限量与限量商品明细、每人限量数、适用门店范围、更新人和时间。提供复制、编辑入口。

## 5. 权限

正式实现至少拆分：

- 页面权限：查看自助餐菜单。
- 字段/动作权限：创建、编辑、复制、启用、停用、维护不限量/限量商品范围。
- 删除权限：与编辑、启停权限独立；删除结果写入操作审计。
- 门店数据范围：列表计数、筛选、门店选择、冲突详情只展示获权门店。
- 商品范围：只能选择当前品牌、当前商品库可供扫码/PAD点餐的商品。

无门店范围不能伪装为空菜单；跨权限范围的冲突不泄露无权菜单名称，但必须提示存在阻塞并给出管理员处理入口。

## 6. 状态与恢复

| 状态 | 页面行为 |
| --- | --- |
| loading | 保留列表骨架并局部加载 |
| first-empty | 解释用途并提供创建菜单主操作 |
| filtered-empty | 保留筛选条件，提供清空筛选 |
| error | 展示重新加载；不清空已保存数据 |
| no-permission | 明确缺少页面权限与门店范围 |
| partial-permission | 只展示获权门店与菜单；跨范围冲突脱敏提示 |
| submitting | 保存按钮 loading、防重复提交、保留当前输入 |
| conflict | 已停用菜单可保存；保存并启用及编辑已启用菜单禁用，并提供原菜单查看/处理入口 |
| concurrent-update | 正式接口接入后展示版本冲突，允许刷新对比后重新提交 |

状态由真实接口结果触发，业务页面不展示“原型状态”切换控件。

## 7. 待业务确认

以下内容没有被写成最终业务事实：

1. 每人限量是否按整段用餐、轮次或餐段累计，以及儿童是否折算数量。
2. 菜单外普通商品是否继续展示并按原价单点，还是只展示菜单内商品。
3. 菜单是否需要餐段/日期有效期；若需要，唯一性键应增加有效时间重叠判断。
4. 是否允许同一菜单关联多张门票；若餐标权益不同，应拆成不同菜单。
5. 是否继续支持选择做法和加料；SPU 新增规格后，点餐端是否自动展示需沿用门店商品的实际售卖规则。
6. 门店能否覆盖品牌菜单，还是只能由品牌/区域统一维护。
7. 点餐额度如何随退票、换票、拼桌、拆桌、转台与订单撤销恢复。

## 8. 生产组件映射

- 列表：`QmList + QmSearch + QmListTable` 或目标模块已验证的表格组件。
- 门店范围：商品中心统一组织/门店选择器，不使用普通 Select。
- 商品范围：复用系统商品选择器的 SPU 模式并返回稳定商品 ID；隐藏 SKUID 条件和列，不再使用逐规格选择组件。
- 表单：复杂联动使用 `qm-form`；三步导航使用现有 Steps 组件。
- 启停与危险确认：统一 Switch、Confirm 与操作审计组件。
- 异步校验：保存/启用接口返回冲突类型、脱敏对象、门店数量和可处理动作。
