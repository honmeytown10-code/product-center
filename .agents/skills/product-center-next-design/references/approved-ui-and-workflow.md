# 商品中心 Next 已确认 UI、交互与推进基线

本文件保存用户已经确认、后续页面必须继承的决策，以及尚未确认、不得擅自写死的机制。设计或实现商品中心 Next 的菜单、页面、弹窗或原型时读取。

## 决策状态

### 已确认

- 本期正式菜单采用五个任务域：商品资料、渠道经营、发布与治理、门店执行、配置；商品工作台作为后续规划，不展示菜单入口。
- 不把所有页面套用同一种布局；页面骨架由业务场景决定。
- 商品工作台本期不建设并从正式菜单隐藏，进入商品中心默认落到“商品主档”；已完成的任务型原型与交互仅作为后续规划参考，不进入本期页面和验收。商品管理采用高密度对象管理布局；渠道商品采用渠道适配布局；发布中心采用预检与批次流程布局；治理页面采用风险闭环布局。
- 每个菜单必须细化到字段、按钮、行操作、批量操作、弹窗/抽屉、状态、权限和异常恢复，不能只交付默认态截图或页面框架。
- 页面之间共享 Console 2.0 外壳、范围上下文、表格密度、状态语言、批量反馈、权限表达和审计表达。
- 已保留的商品工作台后续原型不显示可见滚动条；本期正式页面仍统一避免容器双滚动和无必要的常驻滚动条。
- 页面按“完成一个菜单的完整闭环，再进入下一菜单”推进。
- 本轮必须优化全部正式菜单、页内视图和子页面；渠道分类、渠道属性、四类销售规则、门店分类/属性、开放接口等不得因不是独立左侧菜单而从计划中省略。
- “差异巡检”暂不作为正式左侧菜单；当前治理优先处理未映射、冲突和失效，统一从“映射治理”进入。原巡检页面和历史记录保留为兼容能力，待企迈管理三方渠道具备稳定的平台快照比对和处置闭环后再评估是否恢复独立入口。
- “商品模板”不再作为独立左侧菜单，收敛到“销售规则”页内，并排在“门店售卖规则”之后；模板数据、历史路由和已有操作继续保留，作为逐步弱化的兼容能力。
- 统一管理与分渠道协作使用完全一致的菜单结构，始终保留“商品主档”“渠道商品”和“渠道属性”；后台/前台分类定义及主档默认归属进入商品主档“分类与属性”，渠道商品可覆盖当前商品库前台分类归属；模式只改变渠道商品库数量、职责与流程，不通过隐藏菜单表达。
- 统一管理只有一个品牌默认商品库；分渠道协作可有多个商品库。
- 渠道商品库支持品牌级配置“仅选择已有商品主档 / 允许同时创建主档与渠道商品”。两个协作模式都可使用；统一管理默认推荐开启，分渠道协作由品牌按职责决定。
- 同时创建表单采用“共用资料一次填写、渠道属性同页维护”：前台分类在主档资料区填写一次；渠道名称、主图、结构和规格售价从主档生成且不重复录入；展示资料、售卖设置、补充资料和适用的平台属性仍可在创建时填写。一次提交创建两个独立对象。仅允许标准商品、套餐商品并沿用各自原有类目和字段规则。
- 联合创建页不额外使用“共用资料只填一次”“一次创建两个对象”或结构归属说明卡；主档/渠道页签和字段分区本身承担信息表达，避免占用首屏空间。
- 原型中的“通用菜品”作为完整字段演示类目，一级字段和规格等子字段默认展开；其他类目继续按类目配置和常用字段策略展示。
- 门店售卖规则在新建、编辑和启用前执行范围冲突校验；冲突未解决不得保存或启用。正常列表不提供冲突筛选、冲突计数或“存在冲突”常态状态，历史脏数据通过异常迁移/治理处理。
- 门店售卖规则列表不使用“影响范围”“命中对象”等执行术语；导出明确为“导出规则”，内容为规则对象、经营结果、门店、渠道和状态。状态列仅显示不被裁切的可操作开关，通过 Tooltip 和无障碍名称表达“已启用/已停用”，点击后再确认。
- 门店售卖规则将商品与规格合并为“商品 / 规格”对象：先多选商品，新选商品默认管控整个商品的全部有效 SKU；需要细分时，按商品自身规格组选择实际关联规格值，选中值自动作用于所有包含该值的 SKU，多个值按 SKU 并集展开。不能跨商品选择规格值，也不要求用户逐条选择完整 SKU 组合。做法、加料规则直接从公共做法/加料库按分组多选，默认作用于全部关联商品，仅在例外场景收窄到指定商品。未配置规则时默认全部适用门店可售/可选，新建规则只保留“仅选中门店可售/可选”和“选中门店不可售/不可选”，均使用统一门店选择器。
- 新增/编辑门店售卖规则使用“管控对象 → 门店与渠道 → 校验确认”三步流程；保存前校验对象有效性、商品关系及同门店同渠道的反向结果冲突。
- 门店售卖规则状态列只保留完整可见的开关；规则允许删除，但启用规则必须先停用；删除二次确认，历史审计保留，已发布商品状态不自动回滚。行内“更多”使用独立页面浮层，不能被表格滚动容器或后续行遮挡。
- “同时创建”开启后仍保留“选择已有主档”；新建菜单完整展示标准商品和套餐商品，不得被卡片或列表容器裁切。
- 仅允许从主档添加时，“从商品主档添加”是渠道商品页唯一主操作，使用主色按钮；列表不展示主档编辑入口。
- 允许联合创建时，“新建商品”为主操作，“选择已有主档”为次操作；具备主档编辑权限时可展示独立的“编辑商品主档”。不提供“维护主档与渠道”混合入口。
- 规格、做法、加料结构归主档；渠道只能维护启用子集和销售值。创建可一次编排两个对象，编辑必须分别进入、分别鉴权、分别保存。
- 渠道规格启用按“规格值”管理：禁用一个规格值后，所有包含该值的 SKU 均不可售。规格值列表不在页面常驻展开，从 SKU 销售配置标题区的“配置规格值”进入弹窗修改，页面只显示已禁用数量摘要；SKU 表只维护渠道销售价、市场价、库存和包装配置，不展示主档参考价或 SKU ID。商品标识、商品规格码、商品编码、条码需只读展示。
- 渠道权限以固定 channelId 为稳定授权基础，渠道商品库是按当前动态分组推导的数据范围。拥有渠道商品菜单权限不等于可见全部商品库；商品库切换、选品、计数、批量、导入导出和发布均只使用账号有权渠道推导出的商品库。商品库公共资料写操作需覆盖该库全部渠道，或具备显式共享资料权限；分组变化不得自动扩大固定渠道权限。原型可默认当前账号拥有全部渠道权限，但必须保留这一正式鉴权口径。
- 发布商品至门店使用渠道商品库作为来源时，商品库单选；选定后再从该库选择商品和渠道，切换商品库清空已选对象。批量修改同样先选商品主档或单个渠道商品库，再选择商品；模板、门店目标均提供“全部有权范围 / 指定范围”，提交时固定明确 ID 快照。
- 协作方式继续使用策略页现有单选卡，不在点选时立即切换。用户点击“保存策略”后统一执行普通配置校验与模式迁移校验；模式变化时确认弹窗升级为迁移确认。分渠道转统一只选择一个主商品库，商品取并集且重复商品公共资料以主商品库为准；统一转分渠道时全部商品复制到每个目标商品库。迁移期间当前模式继续生效、策略及受影响渠道商品只读，页面展示简单进度；迁移完成后再切换生效模式。
- 首期模式迁移不建设逐商品/逐字段冲突处理、商品分配矩阵、迁移期间增量编辑、暂停取消、部分重试、自助多版本回滚、独立迁移中心或自定义权限合并；但必须保留保存前校验、迁移快照、原子切换、失败保持原模式、权限不自动扩大和审计记录。
- 商品设置本期只展示“全渠道商品管理策略”一个品牌级配置入口，并直接摘要当前协作方式、商品库、已接入渠道和建品方式；“渠道商品常用字段设置”“渠道字段覆盖规则”暂不展示入口，渠道表单按产品预置规则和固定字段归属运行。
- 京东外卖本期尚未对接，不出现在全渠道策略、商品库分组、渠道统计、模板示例、发布和映射范围；待正式对接后按新增渠道流程补齐能力和需求。

### 待确认，不得写死

- 任务的最终创建规则、负责人路由、SLA、升级、提醒和转交权限。
- 统一维护与分渠道协作在具体客户上的默认模式和切换权限。
- 生产接口、权限码、角色清单、消息渠道和审计保留周期。
- 菜单路由、旧入口迁移、灰度范围和发布节奏。

## 共享视觉基线

- 使用 Console 2.0 白色顶栏、白色菜单和浅灰业务背景；主色跟随基座主题变量，默认绿色 `#00b460`。
- 字号使用 14px 基础、12px 辅助、16–20px 页面标题；间距只使用 4/8/12/16/24px。
- 内容外边距 12px，外层容器圆角 8px；不使用营销页式大标题、渐变背景、低密度大卡片或超大圆角。
- 数据列表与对象管理页默认不展示“大标题 + 页面说明 + 范围说明条”的叠加头部；进入菜单后直接呈现状态、筛选、对象导航和数据表。只有范围会改变可编辑字段或提交目标时，才保留单行紧凑范围条。
- 商品主档左侧快捷导航默认使用后台分类，不使用只有两项的商品类型占据整栏；商品类型保留为结构化筛选。渠道商品左侧使用当前商品库最终有效的前台分类筛选；渠道资料页可覆盖商品归属，但分类定义仍回商品主档维护。
- 范围上下文需要出现时使用紧凑横条，明确品牌、协作方式、商品库/渠道、门店和更新时间，不重复解释页面职责。
- 商品图片只用于识别，通常 40–48px；名称、编码和少量状态组成稳定商品识别单元。
- 表格是大量对象页面的默认载体；卡片只用于少量复杂策略，不把所有页面卡片化。
- 状态必须有文字，颜色和图标只辅助；错误红色只用于失败、危险、异常和逾期。
- 行内高频操作不超过 3 个，其余收进“更多”。每页只突出一个主操作。
- 1440px 为最低桌面基线；长文本截断并可查看完整值。关键列稳定可见，固定列数量克制。
- 隐藏可见滚动条不等于禁用滚动；内容溢出时仍允许鼠标滚轮、触控板和键盘访问。

## 共享交互基线

- 所有筛选作用于同一结果集，条件变化回到第一页；筛选空保留条件并提供清空或调整入口。
- 搜索负责名称、编码等关键词，高级筛选负责结构化条件，不把全部条件塞入一个输入框。
- 批量选择后出现稳定批量操作区，显示已选数量、商品数、渠道数和门店数；结果显示成功、失败、等待和失败原因。
- 抽屉用于保留列表上下文的查看或轻编辑；弹窗用于单一短任务；长表单和复杂配置进入独立页面。
- 高风险操作说明真实对象、范围、生效时间、不可逆部分、恢复方式和审计结果。
- 保存和提交防重复；离开长表单提示未保存变更；异步任务跳转到可验证的任务或批次结果。
- 无权限状态不得伪装为空数据；字段无权、动作无权和范围无权分别处理。
- 每页覆盖 loading、success、first-empty、filtered-empty、error、no-permission、partial-permission、submitting；适用时增加 partial-success、并发冲突、授权失效、渠道限流和异步等待。

## 任务机制建议稿

工作台原型当前使用本地模拟数据，只验证信息架构和交互，不代表任务类型、负责人或 SLA 已经写死。

推荐采用“内置领域任务 + 可配置路由”，而不是完全写死，也不在第一阶段建设任意 BPM 设计器：

1. 系统内置任务事件和状态机，保证业务语义稳定。
2. 品牌按职责范围配置负责人路由、SLA、提醒和升级规则。
3. 运行时根据事件对象、品牌、渠道、门店、角色和权限解析负责人。
4. 无匹配负责人时进入明确兜底队列，不静默丢失任务。
5. 转交、认领、协办、完成、忽略和重开全部保留审计记录。

### 建议内置任务来源

| 来源 | 示例 | 默认触发时机 |
| --- | --- | --- |
| 资料校验 | 缺少类目、图片、价格或平台字段 | 保存、预检或定时巡检后 |
| 主档变更 | 新增规格、停用结构、关系变化 | 主档保存后影响下游时 |
| 渠道确认 | 渠道团队需确认新结构或销售资料 | 分渠道协作模式下 |
| 发布执行 | 发布失败、部分成功、授权失效、渠道限流 | 发布任务返回结果时 |
| 映射治理 | 未映射、冲突、失效 | 发布、拉取或映射校验后 |
| 平台差异（兼容能力） | 企迈管理三方渠道的平台值与成功发布快照不一致 | 仅在具备稳定读取、比对和处置闭环时触发，不形成独立菜单 |

### 建议负责人解析顺序

```text
对象指定负责人
→ 渠道/商品库责任人
→ 区域或门店责任人
→ 任务类型默认角色
→ 品牌管理员兜底队列
```

任务创建规则、职责路由、SLA 和升级规则必须分别建模，不把“负责人是谁”硬编码在页面或单个任务类型中。页面展示解析结果、来源和可转交范围；配置入口是否在“全渠道配置”或独立“任务规则”页，待真实角色和配置频率确认后决定。

## 单菜单交付流程

每个菜单严格按以下顺序完成：

1. 架构契约：目标角色、主任务、对象、范围、上下游、统一/分渠道差异。
2. 字段级规格：视图、筛选、表格、详情、表单字段及来源、默认、校验、权限、动态条件。
3. 动作级规格：页面按钮、行按钮、批量操作、更多菜单及显示/禁用/loading/结果规则。
4. 容器级规格：弹窗、抽屉、向导、二次确认、未保存和失败恢复。
5. 状态与权限矩阵：正常、空、失败、无权、部分成功、异步和高风险状态。
6. 高保真原型：核心链路可操作，使用真实业务示例，不用静态假控件。
7. 验收：1440px、长文案、关键状态、主链路、构建和业务语义检查。
8. 用户确认：记录新增已确认决策和待决项，再进入下一菜单。

## 后续页面顺序

完整范围以 [page-worktree.md](page-worktree.md) 为唯一工作树；以下只表达批次依赖，不代替页面清单：

1. 商品资料全域：商品管理/主档、分类与属性全部视图、配方与营养全部视图。
2. 渠道经营全域：渠道商品及渠道分类/属性、销售规则（含门店售卖规则、商品模板、价格策略、属性互斥、必选商品）、商品推荐。
3. 发布与治理全域：发布中心、映射治理；差异巡检仅保留兼容能力和历史记录，不作为当前正式菜单验收项。
4. 门店执行全域：商品、覆盖门店、门店分类、门店属性、区域策略。
5. 配置与开放全域：商品设置（含全渠道商品管理策略）、开放接口。
6. 全量一致性、旧功能归属与迁移验收。

## 完成定义

页面只有在“菜单 × 页面/视图 × 字段 × 按钮 × 弹窗 × 状态 × 权限”覆盖矩阵完整、核心原型链路可操作、无已知 P0/P1/P2 问题且用户确认后，才能标记为完成。任何真实接口、权限或任务机制未确认时必须明确标为待接入/待决，不得用原型本地数据冒充最终业务规则。
