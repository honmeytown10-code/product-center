# 销售规则模块交互与 UI 设计

## 1. 模块范围

本轮覆盖价格策略、门店售卖规则、属性互斥、必选商品。页面只重构信息密度、操作反馈、弹层与风险提示，不改动现有规则字段和业务口径。

## 2. 共同约束

- 列表页去除大标题与大段说明，以筛选、统计和规则表为核心。
- 同一页面仅保留一个实心主按钮；次要入口使用描边按钮或更多菜单。
- 保存规则配置不等于发布。价格与门店商品的实际变更仍由发布流程执行。
- 启停、删除必须说明对象、门店/渠道范围、生效时点、已发布数据是否回滚；反向范围冲突在保存或启用前阻断，不允许生成新的冲突规则。
- 抽屉和弹窗覆盖页面，不改变列表宽度。

## 3. 价格策略

列表字段为策略名称、策略 ID、机构门店、生效渠道、生效日期/周期/时段、启用状态、操作。支持策略 ID、策略名称、机构门店、启用状态筛选；支持价格管理、编辑、复制、删除，以及门店和时间详情抽屉。新建与复制策略默认停用。

启用时说明后续发布将按策略计算渠道价格；停用后不参与后续发布，已下发价格保持不变；删除不可恢复，已下发价格不自动回滚，可从发布记录追溯。

## 4. 门店售卖规则

列表字段为规则名称、规则 ID/更新时间、管控对象、经营结果、适用门店、适用渠道、启停状态、操作。支持对象类型、状态和关键词组合筛选，全选/逐行选择、批量停用和规则导出。导出内容为规则定义、商品、门店、渠道和状态，不使用“影响范围”“命中对象”等系统执行术语。

编辑抽屉保留商品/规格/做法/加料、经营结果、门店和渠道字段，并拆成“管控对象 → 门店与渠道 → 校验确认”三步。商品规则直接多选商品；规格规则先选商品，再从各商品下选择完整 SKU 组合；做法、加料规则直接从公共定义库选择，默认影响全部关联商品，仅在例外场景选择指定商品收窄范围。

“仅选中门店可售/可选”和“选中门店不可售/不可选”必须使用统一门店选择器，表单只回显已选数量与部分门店名称；选择器支持按门店名称/编码、组织、区域和门店类型筛选。未配置规则时商品、规格、做法和加料默认在全部适用门店可售/可选，因此新建规则不再提供“全部适用门店可售/可选”。

状态列使用带文字的可操作开关并保证完整显示，点击后进行二次确认。创建、编辑和启用前校验反向规则冲突；存在冲突时定位原规则并要求调整范围，不能覆盖确认后继续保存。启停前展示商品、门店和渠道数量；已发布门店商品不会自动上下架。规则支持删除，但启用规则必须先停用；删除二次确认且保留审计记录，已发布商品状态不自动回滚。

## 5. 属性互斥

列表字段为规则名称、规则 ID、基础规格/做法/加料、互斥规格/做法/加料、状态、操作。条件组与互斥组一一对应，可新增/移除条件组；规格、做法、加料分别选择并以可移除标签展示。

适用商品保留全部商品、指定商品、指定商品不适用三种原有范围。保存校验规则名称、每组两侧配置及指定商品范围。启用时提示客户端兼容要求；停用只影响新订单校验；删除不可恢复。

## 6. 必选商品

列表字段为方案名称、方案 ID、商品/分类名称、对象类型、适用门店、更新时间、操作。保留方案名称、商品必选、堂食/外卖、固定数量/与用餐人数相同、适用门店等现有字段。

必选商品通过选择弹窗添加，删除前确认。门店支持名称/编码筛选、门店类型筛选、三栏选择和文件导入校验。保存校验方案名称、必选商品、售卖类型和适用门店。特例设置记录必选方案、豁免门店和原因。

## 7. 待生产接入

- 列表、详情、启停、删除、复制、导入、导出接入真实 API 与权限点。
- 启停和删除记录操作人、原因、时间及变更前后值。
- 发布中心消费价格和售卖范围规则版本，并显示命中、冲突和失败原因。
- 属性互斥与必选规则按真实客户端版本、订单渠道和门店能力做二次校验。
