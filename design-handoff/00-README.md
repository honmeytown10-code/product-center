# Design 交付包 — 全渠道商品管理策略重设计

claude.ai/design 是网页端工具，无法访问本地磁盘，也无法读取代码仓库。这个目录把它需要的一切打包成可上传的材料，让它在**你现有产品逻辑**的基础上重设计，而不是生成一个通用后台模板。

---

## 文件清单

| 文件 | 作用 | 上传给 Design |
|---|---|---|
| `01-context-brief.md` | 业务模型、页面现状结构、设计规范、现状问题、改版目标 | ✅ 必传 |
| `02-current-ui-snapshot.html` | 现状界面的像素级还原，7 块展板覆盖全部关键状态 + 设计 Token | ✅ 必传 |
| `03-interaction-spec.md` | 逐控件、逐状态、逐转移的精确规格；危险操作清单；状态矩阵缺口 | ✅ 必传 |
| `00-README.md` | 本文件，使用说明 | ❌ 不用传 |
| `04-conversation-ui-baseline.md` | 本次对话确认的不可变 UI、字段与策略基线 | 内部实现必读 |
| `06`–`10` 模块文件 | 已落地模块的字段、动作、弹层和能力边界 | 内部实现必读 |
| `11-full-page-coverage-checklist.md` | 全部正式菜单与稳定子页的最终覆盖索引 | 验收必读 |

`02` 可以直接用浏览器打开查看。它是单文件、零依赖、纯 CSS 的静态页面，尺寸和色值全部取自生产代码，画板宽度 1440px（设计基准宽度）。

---

## 使用步骤

1. 打开 claude.ai/design，新建一个对话。
2. 把 `01`、`02`、`03` 三个文件**一起**上传。三份材料互补，缺一份 Design 就会开始猜：
   - 只有 `01` → 懂业务但不知道现在长什么样，容易推翻既有视觉语言
   - 只有 `02` → 看得见界面但不懂业务约束，容易把"必须的"当成"多余的"
   - 缺 `03` → 不知道有哪些状态和危险操作，产出只覆盖正常态
3. 用下面的起手提示词。

## 重点提醒 Design 关注的问题

如果它第一轮没主动处理，把这几条追加给它。这是我读代码 + 实跑页面后判断的核心问题，按优先级排：

1. **没有影响预览。** 这是一个改一下就会重排整个商品中心工作流的页面（左侧菜单模块增减、商品编辑入口结构、分权模型全都跟着变），但保存前用户看不到「我这次改动会导致什么」。设计基线明确要求「修改影响下游渠道时必须先解释影响范围，再允许保存」。

2. **信息量最大的部分被藏进弹窗。** 渠道商品库分组最需要通盘看，却塞在 920px 弹窗里再做左右分栏 + 二级编辑态，层级三层深。而且弹窗内的校验提示渲染在页面顶部——被弹窗自己盖住，用户根本看不见。

3. **两个 section 版面并列、业务上却有依赖。** 只有在 Section 2 被设为「企迈管理」的三方渠道，才会进入 Section 1 的分组体系。这层因果关系现在要用户自己在脑子里拼。

4. **只读与可编辑视觉相近。** 「企迈管理」模式下能力是两个绿色只读标签，「平台管理」下是两个 checkbox，同一列同一位置交替出现，可点性相反。

5. **9 个渠道只有 6 个出现在页面上。** POS 和两个小程序渠道只在分组弹窗里露面，用户没有任何一处能看到品牌全部渠道的当前状态全景。

6. **渠道的业务差异完全不可见。** 品牌级 vs 门店级作用域、是否需要品牌审核、是否涉及服务商计费——这些真实影响决策的字段代码里都有，UI 一个没显示（清单见 03 第 8 节）。
