# 商品中心 Next 信息架构

## 导航模型

使用不可点击的轻量分区标题和可点击页面入口：

```text
商品资料
  商品主档
  分类与属性
  配方与营养

渠道经营
  渠道商品
  渠道属性
  销售规则
    门店售卖规则
    商品模板（兼容能力）
    价格策略
    属性互斥
    必选商品
  商品推荐

发布与治理
  发布中心
  映射治理

门店执行
  门店商品

配置
  商品设置（包含全渠道商品管理策略、通用设置与字段设置）
  开放接口（按能力展示）
```

“平台商品”不再作为独立历史系统分区。平台扩展字段进入渠道商品，平台发布进入发布中心，平台真实商品与关联问题进入映射治理。商品工作台和差异巡检本期不设置正式菜单，只保留原型/历史路由与后续规划；商品中心默认进入商品主档。

## 统一管理模式

- 菜单结构与分渠道协作完全一致，始终显示“商品主档”“渠道商品”和“渠道属性”；协作方式不得通过隐藏菜单改变用户心智。
- 渠道商品页只有一个“品牌默认商品库”，不显示无意义的多商品库切换。
- 商品主档仍负责身份与结构；渠道商品仍负责销售资料，底层对象及字段归属不合并。
- 品牌可允许从渠道商品库直接新建商品：表单按“主档资料 / 渠道商品资料”分区，一次提交同时创建主档和默认渠道商品。
- 发布时以默认渠道商品生成快照，用户只看到目标渠道、门店和影响范围。

## 分渠道协作模式

- 菜单显示“商品主档”和“渠道商品”。
- 在“渠道商品”后显示“渠道属性”，承接描述标签、角标、系列与渠道自定义属性；后台/前台分类定义统一归商品主档“分类与属性”，渠道商品资料页可覆盖当前商品库的前台分类归属。
- 商品团队只维护身份、SKU 结构和候选关系。
- 渠道负责人从主档选择商品加入授权渠道商品库，维护渠道销售资料和平台扩展。
- 品牌也可开启“同时创建主档与渠道商品”；开启后，具备双重权限的渠道负责人可在当前商品库中一次完成创建，未开启时仍只允许选择已有主档。
- 渠道商品页持续显示当前商品库、包含渠道、权限范围和待处理数量。
- 模板来源由适用渠道自动计算；来源不唯一时要求拆分模板。

## 页面边界

| 页面 | 核心任务 | 不承接 |
| --- | --- | --- |
| 商品工作台（后续规划） | 后续查看本人职责内待完善、待发布、失败和映射风险；本期无入口、不研发、不验收 | 不作为静态数据看板，不复制全部列表 |
| 商品主档 | 建立商品身份与结构 | 不维护渠道销售资料、门店即时库存或映射 |
| 分类与属性 | 维护后台分类、前台分类、规格、做法、加料和展示属性的基础定义 | 不维护单商品结构关系，不承担配方计算 |
| 配方与营养 | 管理配料库、商品配方、门店配方策略和营养成分 | 不承担渠道销售字段 |
| 渠道商品 | 从主档选择商品，或按品牌策略同时创建主档与当前渠道商品；维护品牌级渠道售卖资料和平台扩展 | 不创建独立 SKU，不维护平台自维护商品资料 |
| 渠道属性 | 维护描述标签、角标、系列与渠道自定义属性定义 | 不修改商品主档身份、后台/前台分类、规格结构或平台权威字段 |
| 销售规则 | 以页内视图管理门店售卖规则、商品模板、价格、必选/互斥等跨商品经营规则 | 商品模板不再形成独立菜单；模板仍不手工选择商品来源，不维护品牌级渠道资料 |
| 商品推荐 | 管理商品、分类、渠道和门店范围内的推荐关系 | 不承担通用销售规则 |
| 发布中心 | 创建发布批次、预检、查看任务、诊断和重试 | 不作为商品资料编辑器，不把批量修改全部塞入发布流程 |
| 映射治理 | 处理未映射、冲突、失效及其影响范围 | 不维护平台商品权威资料 |
| 差异巡检（兼容能力） | 在具备稳定平台读取和处置闭环时，比较企迈管理渠道的发布快照与平台现状 | 不设正式菜单；平台自维护渠道不比较或覆盖平台资料 |
| 门店商品 | 查看和批量处理门店实际可售商品、上下架、库存和沽清 | 品牌后台不新建、导入或重建商品结构 |
| 商品设置 | 管理全渠道商品管理策略、低频通用参数和常用字段；全渠道策略作为页内配置入口 | 不维护门店授权令牌和合同开通边界，不承接能形成独立高频工作流的业务模块 |

门店与平台店铺绑定、授权令牌、续期、换绑和解绑属于平台服务或公共连接中心，不设为商品中心菜单。商品中心仅在渠道商品、发布、映射等相关上下文展示绑定状态、异常原因和外部处理入口，不维护其权威数据。

## 渠道商品库权限边界

- 权限采用“页面权限 + 商品库数据范围 + 操作权限”三层模型。拥有“渠道商品”菜单权限不等于可查看全部渠道商品库。
- 商品库数据范围按稳定商品库 ID 授权；列表、数量、搜索、导入导出、待办和发布范围只统计用户获权商品库，禁止泄露其他商品库名称、商品数量和经营数据。
- 商品库重命名不改变授权；删除、合并或协作方式切换必须做权限影响分析并保留审计。
- 统一管理只有一个默认商品库，但仍需显式授权。由多商品库切换为统一管理时，原部分商品库权限不得自动扩张为全品牌权限；品牌管理员需确认默认商品库的新授权范围。
- “同时创建主档与渠道商品”需要同时具备商品主档创建权限和当前商品库的渠道商品创建权限；只有渠道商品权限时，只能选择已有主档或提交主档创建申请。
- 渠道商品列表默认进入“维护渠道资料”，不提供联合编辑入口。仅允许选择已有主档时不展示主档编辑动作；允许联合创建且具备 `product_master.edit` 时，可展示独立的“编辑商品主档”并进入主档页面。创建策略不得替代主档编辑权限。
- 原型可默认模拟拥有全部商品库权限，但正式需求、接口和验收必须覆盖无商品库权限、部分商品库权限和跨商品库批量操作。

## 功能归属规则

1. 用户是否会从独立入口开始一项稳定任务，是决定菜单入口的第一标准。
2. 同一对象的状态、范围或表现方式使用 Tab、视图或筛选，不拆菜单。
3. 异步、跨渠道、可部分成功的操作统一进入发布中心或任务中心。
4. 影响商品身份与结构的能力归商品资料；影响渠道卖法的能力归渠道经营；影响具体门店即时状态的能力归门店执行。
5. 未映射、冲突和失效达到跨对象处理规模时进入映射治理；资料差异仅在具备稳定比对与处置闭环后再评估独立治理入口。
6. 低频、高风险、品牌级策略归配置，并提供影响分析和受控迁移。
